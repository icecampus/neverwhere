# Ускорение арт-итераций в PGG — план доработок по итогам сессии `spire_house`

**Статус:** план (2026-09-11), ничего не реализовано. Продолжение `agent_tooling_plan.md`: там цикл «правка → картинка + числа» стал быстрым (секунды, один MCP-вызов); здесь — что мешало, когда агент 37 запросов подряд делал **арт-правки** готового здания (`resources/pgg/spire_house.pgg` + `spire_house/*.pgg`): окна, карнизы, черепица, коньки, кладка, покраска.

Каждый пункт привязан к инциденту сессии. Исполнитель — другой агент; пункты независимы, если не сказано иначе. Порядок разделов = рекомендуемый порядок работ (сначала дешёвое с наибольшим эффектом).

## 0. Что показал транскрипт

~600 вызовов инструментов на 37 запросов: 219 `Read`, 149 правок, 96 `Grep`, 73 `pgg_render` (+ ~70 чтений PNG), 20 `pgg_load`, 3 `pgg_probe`, **0 `pgg_docs`**, 22 `GetDynamicTools`.

Самые дорогие запросы:

| Запрос | Шагов | Что жгло шаги |
|---|---|---|
| Подрезать кирпичи по контуру арки | 56 | 20 grep по спеке (`clip`, `sdf_*`, `boolean`, `sin/cos`, `@P`, `merge`, `repeat`, `empty`, `cap_group`), тернарник с двумя `geo<mesh>` → переписка в два def'а |
| Коньковые уголки вместо валика | 43 | 13 правок, 6 рендеров подбором, 5 grep по C++ ядру ради порядка осей `orient_from_euler` |
| Шпиль: черепица по граням + коньки | 43 | 16 правок, 9 рендеров; скопирован незамеченный баг мансарды |
| Мелкая кладка на стенах | 40 | 18 правок — boilerplate на 4 стены × N проёмов, 6 граней × поворот |
| Расширить фасад до равных простенков | 32 | 3 захода в формулу, 5 рендеров, 2 probe: нечем измерить расстояние между деталями |
| Убрать слуховое окно | 32 | 9 правок: элемент размазан по нескольким def'ам и вырезу в черепице |

Пять корневых причин:

1. **Поиск «есть ли в языке X»** идёт grep'ом по спеке на 1100+ строк, а не через `pgg_docs`/cheatsheet.
2. **Семантические грабли** узнаются методом тыка, по одному циклу правка → load → ошибка каждая.
3. **Камера подбирается вручную** (`target="x,y,z"`, `zoom`) — повторные рендеры «попал ли кадр».
4. **Измерения делаются глазами** — `pgg_probe` даёт bbox только целого биндинга.
5. **Регрессии находит пользователь**: после правки рендерится один удобный ракурс, а не фиксированный набор видов; правка общего def'а не проверяется у всех потребителей.

## 1. Этап A — знания: cheatsheet и rule (документация, без кода)

**Инциденты:** 20 grep по спеке в одной задаче; `orient_from_euler` — порядок осей искали в `builtins_fields.cpp` и `glm::eulerAngle*`; `pgg_docs` не вызывался ни разу, хотя поддерживает `builtin:<name>`.

### A1. `docs/pgg/cheatsheet.md` — одна страница

Содержимое, в этом порядке:

1. **Builtin'ы одной строкой** — сигнатура + 5–10 слов, сгруппированы как в §8 спеки (источники, трансформы, топология, поля, scatter, sdf, bake). Без прозы: страница должна читаться целиком одним `Read`. Источник — `src/libs/pgg/src/eval/builtin_docs.cpp` (сгенерировать скриптом или `PggTool docs` по каждому имени; допустимо ручное составление, но тогда в шапке — дата и версия спеки).
2. **Функции выражений и атрибуты** — `sin/cos/atan2/...` (радианы!), `radians()`, `mix/clamp/smoothstep`, конструкторы `vec3()`, касты, `@P/@N/@index/@iteration/@tint/@Cd`, `ingroup()`.
3. **Идиомы** (по одному примеру в 3–6 строк): покраска цепочкой тернарников + `edge_mul`; `repeat` с `merge(acc, ...)`; `instance_on_points` с `variants` и `@tint`; `clip` полупространствами с `cap_group`; `bevel(..., bevel_group = "edge")` + `compute_normals(mode = flat)`; `sweep` по `mesh_line` с `profile_scale`.
4. **Грабли семантики** — из этой сессии обязательно:
   - тернарник **не объединяет два разных `geo<mesh>`** — выбор геометрии выносить в отдельные def'ы или в числовые параметры (пример: `hexa_brick_face` / `hexa_brick_clock_face` в `spire_house/common.pgg`);
   - `sweep` по вертикальному пути **меняет оси профиля местами** (`profile_scale` = `(depth, width)`, не `(width, depth)`) — усечённая пирамида крыши стояла боком;
   - `parts.cbox`/`parts.piece` считают фаску `k` от **минимального** размера — на призме этажа это ~40 см, грани визуально «загибаются»; для больших объёмов — голый `box` или `bevel` с абсолютной шириной;
   - пустого меша нет — идиома `mesh_line(count = 0, length = 0.0)` как нейтраль для `repeat`/`merge`;
   - `orient_from_euler(rot)` — градусы, порядок применения осей (уточнить по `builtins_fields.cpp` и записать явно);
   - вписанный/описанный радиус правильного шестигранника: `r_out = r_in * 1.1547` (2/√3); выносы поясов на многоугольнике задавать **по нормали к грани**, иначе на вершинах вынос другой;
   - при укладке рядов на скате смещение «по нормали на ряд» после поворота становится выносом от поверхности — верхние ряды отрываются; нахлёст задавать **только вдоль ската** (шаг ряда < длина плитки), отступ по нормали — константа;
   - камера `pgg_render` **липкая**: `target`/`zoom`/`orbit` сохраняются между вызовами; `target=""` сбрасывает;
   - `@tint` — множитель, нейтраль белая; в `merge` с неокрашенным `@tint` не обнуляется (v1.17), но `* @tint` на группах без якорей всё равно проверять кадром.
5. **Шаблоны MCP-вызовов** (см. A2) — чтобы после суммаризации контекста не переоткрывать схемы.

Ссылку добавить в `docs/pgg/README.md` (таблица) и в раздел «PGG» `AGENTS.md` одной строкой: «перед grep по спеке — `pgg_docs(symbol)` или `cheatsheet.md`».

### A2. Rule для `resources/pgg/**`

Файл `.cursor/rules/pgg-authoring.mdc` с `globs: resources/pgg/**/*.pgg` (см. skill `create-rule`). Содержимое — короткое, императивное:

- порядок поиска семантики: `pgg_docs("builtin:<name>")` → `docs/pgg/cheatsheet.md` → спека §8 → ядро;
- цикл правки: правка → `pgg_render(node, view=...)` (F4 сам перечитает файл; `pgg_load` — только для новой сессии или немедленной статической проверки) → при непонятной разнице `compare="prev"`;
- перед «готово»: контакт-лист видов файла (см. C1) и рендер **всех потребителей** изменённого общего def'а (grep по имени def'а в `resources/pgg`);
- аргументы `pgg_render`/`pgg_probe` в одну строку каждый (node, target, orbit, zoom, ortho, chrome, size, compare; spec);
- грабли из A1 п.4 — ссылкой, не копией.

**Приёмка A:** новый агент по запросу «подрежь кладку по арке с зазором» находит `clip` + `cap_group` + идиому полупространств за ≤ 3 чтения, не открывая спеку.

## 2. Этап B — библиотека `resources/pgg/lib` (убрать boilerplate)

**Инциденты:** 6 ручных `bf0…bf300 = transform(hexa_brick_face(...), rotate = vec3(0, k*60, 0))` в `tower.pgg` и 3 в `bay.pgg`; 4 стены `wall_f/b/r/l` с ручными `rotate`/`translate` в `brick_box_veneer`; `hexa_frustum`, `hexa_belt`, `hexa_corbel`, `hexa_dentils`, `clip_arch_hole`, `clip_circle_hole`, `clip_wedge_out` живут в `spire_house/common.pgg`, хотя это общая каменная/кирпичная архитектура; тот же паттерн «раствор под облицовкой» отдельно изобретён в `stone_bridge.pgg` (`mortar_skin`) и в `spire_house` (`brick_prism` группы `mortar` + `brick_rows`).

### B1. `lib.shapes` / `lib.parts`: массивы и многоугольники

- `polar_array(g: geo<mesh>, n: int, step_deg: f32 = 360/n, axis: vec3 = (0,1,0)) -> geo<mesh>` — `repeat` с `merge(acc, transform(g, rotate = ...))`.
- `around_box(g_front: geo<mesh>, w: f32, d: f32) -> geo<mesh>` — одна «фасадная» деталь, повёрнутая на 4 стены прямоугольника w×d (лицо +Z → +Z, −Z, +X, −X).
- `ngon_frustum(y0, y1, r0, r1, sides: int, grp)` — обобщение `octa_frustum`/`hexa_frustum` (`spire_house/common.pgg`), радиусы — **апофемы** (расстояние до грани), внутри пересчёт в описанный; это убирает `1.1547` из пользовательского кода. Документировать угол поворота профиля, чтобы плоская грань смотрела в +Z.
- `ngon_belt(y, h, r, sides, over_lo, over_hi)` — перенос `hexa_belt` с фаской `bevel_group = "edge"`.

### B2. `lib.masonry`: подрезка кладки по проёмам

Перенести из `spire_house/common.pgg` в `lib.masonry` (с docstring'ами и без привязки к `spire_house`):

- `clip_wedge_out(g, cx, cy, R, deg0, deg1)`, `clip_arch_hole(g, cx, y_bot, win_w, win_h, bar, gap)`, `clip_circle_hole(g, cx, cy, R)` — режут **готовый меш** кирпичей полупространствами (без SDF-булевых), 12 секторов на полуокружность / 12 на круг. Параметр `segments` вместо константы.
- `clip_rect_hole(g, cx, y0, w, h, gap)` — прямоугольный аналог для дверей/ниш без арки.

### B3. `lib.blockwork`: облицовка поверх сердцевины

- `brick_veneer_rows(len, h, L = 0.17, ch = 0.12, g0 = 0.008, z = 0.03)` — обёртка над `coursed_wall_anchors` (сейчас `spire_house/common.brick_rows`).
- `brick_veneer(rows, rng, L, bh, t, k = 0.14, grp = "brick")` — инстансинг ¼/½/¾/1 ложков с `@tint` (сейчас `brick_from_rows`).
- `core_prism(w, d, h, y0, grp = "mortar")` — прямой `box` без фаски (сейчас `brick_prism`); в docstring — почему не `cbox`.
- Идиома в cheatsheet: «сердцевина `mortar` + облицовка `brick` + `clip_*_hole` по проёмам»; покраска `mortar` — тёмно-серый (`(0.12,0.118,0.112)…(0.07,0.068,0.065)`), см. `spire_house/assemble.pgg`.

### B4. `lib.roofing` (новый модуль): черепица и коньки

Из `spire_house/roof.pgg` вынести и обобщить:

- `tile_field(w_along, slope_len, tw, tl, th, pu, pv, lift, rng)` — ряды вразбежку на **общей сетке** (не самоцентрирующиеся), константный отступ по нормали `th*0.5 + lift`, нахлёст только вдоль ската (`pv < tl`), ±1 мм джиттер;
- `tile_face_tri(...)` — то же + `clip` по двум рёбрам треугольной грани (сейчас `spire_tile_face`);
- `hip_caps(p0, p1, rng, half, lift, cap_w, cap_l, y_step)` — коньковые уголки внахлёст вдоль ребра: `lift + index * y_step`, первый уголок утоплен на `cap_l * 0.40`, клип по карнизу `p0 - (0, 0.05, 0)`; в docstring — оба бага сессии (плитки отрываются от ската при накоплении по нормали; коньки сливаются в плоскость без `y_step`).

После переноса `spire_house/*.pgg` и `cottage*/*.pgg` переключить на lib, `spire_house/common.pgg` оставить только специфичное. Удалить мёртвый код `spire_lucarne`, `hexa_ring`, `cone_r` в `spire_house/common.pgg`.

**Приёмка B:** `tower.pgg::clock_tier` собирает 6 граней кладки одной строкой через `polar_array`; в `resources/pgg` нет литерала `1.1547` вне `lib`; тесты корпуса (`src/tests/pgg`) зелёные, кадр `house` по `pgg_diff` без изменений (или с ожидаемыми, зафиксированными в коммите).

## 3. Этап C — Viewer/RPC: именованные виды, контакт-лист, измерения

**Инциденты:** 73 рендера, из них десятки — повтор с подправленным `target="x,y,z"`/`zoom` («прошлый кадр попал в эркер, а не в простенок»); `binding:` работает только для верхнеуровневых биндингов, `group:` — по материалам; расстояние «колоннетта эркера ↔ внутренний край квойнов» считали руками по `blockwork.pgg`; `compare="prev"` использовался 4 раза из 73.

Файлы: `src/apps/PggViewer/ViewerRpcServer.cpp` (команды), `tools/pgg_mcp/server.py` (MCP-обёртка), `docs/pgg/viewer_rpc.md` (контракт), `src/libs/pgg/src/eval/probe.cpp` (инспекторы).

### C1. Именованные виды (`views`)

- Файл `<name>.views.json` рядом с `.pgg` (не в языке — камера не часть геометрии): массив `{name, node, target, orbit, zoom, ortho?, chrome?, size?}`. Для `spire_house.pgg` сразу завести: `front`, `front_right_wing`, `bay_close`, `belt_junction`, `roof_hip`, `spire_top`, `wall_joints` — с координатами из этой сессии (они в транскрипте/файлах `tmp/pgg_rpc_shots/*`).
- RPC `render {view: "<name>"}` — подставляет параметры вида; явные аргументы перекрывают. RPC `views {}` — список. MCP: `pgg_render(view=...)`, `pgg_views()`.
- `render {views: [...]}` или `pgg_contact_sheet(views=[...])` → **один PNG** сетка N×M с подписями (имена видов) + массив статов. Реализация — на стороне MCP (Pillow уже допустим? проверить `tools/pgg_mcp/requirements.txt`; если нет — склейка в C++ через существующий `capturePng`).
- В rule (A2): «перед “готово” — `pgg_contact_sheet(views="*")` + `compare="prev"`».

### C2. Нацеливание на деталь

- `target="binding:<путь>"` расширить до **вложенных** биндингов внутри def'а: `binding:bay_unit/f2_wins` (путь как в пробниках `path:inspector`). Движок уже знает bbox каждого закэшированного биндинга — использовать его, не пересчитывать.
- `target="group:<grp>@<binding>"` — bbox группы внутри конкретного биндинга (сейчас — по всему прогону).
- В ответе `render` — `camera.target_bbox`, чтобы агент видел, во что попал, до чтения PNG.

### C3. Измерения числами

- Инспектор `bbox[group=<grp>]` в `pgg_probe`: `"bay_unit:bbox[group=stone]"` → min/max/center/size.
- Инспектор `gap[a=<path|group>, b=<path|group>, axis=x|y|z]` → зазор между bbox'ами по оси (с знаком: перекрытие отрицательное). Закрывает задачу «зазор башня→окно = окно→квойны» одним вызовом.
- `pgg_measure(a, b, axis)` в MCP как сахар над `gap`.

### C4. Дешёвая проверка «не сломал»

- `render` без чтения PNG: `pgg_render(..., png=false)` — только статы + `compare` (changed_pct, bbox). PNG читать, только если `changed_pct` вне ожидаемого.
- `compare="baseline"` — diff с кадром, снятым `pgg_load(snapshot=true)`/`pgg_views` в начале задачи, а не только с предыдущим (предыдущий часто — промежуточный).

**Приёмка C:** задача «выровнять окна от квойнов на боковых стенах» решается за 1 `pgg_measure` + 1 правка + 1 `pgg_render(view="side_wing", compare="prev")`; полный обход `spire_house` перед коммитом — один `pgg_contact_sheet`.

## 4. Этап D — ядро языка (мелкие, но частые)

**Инциденты:** тернарник с двумя `geo<mesh>` (переписка в отдельные def'ы); `mesh_line(count = 0)` как пустой меш; `sweep` меняет оси профиля; фаска от минимального размера.

- D1. `select(cond: bool, a: geo<T>, b: geo<T>) -> geo<T>` — builtin выбора геометрии по **статическому/параметрическому** условию (без вычисления обеих веток, если условие — константа/параметр). Либо разрешить тернарник для одинаковых `geo<T>` — решить по спеке §6.3, обновить §8 и `typecheck.cpp`, тест в корпусе.
- D2. `empty_mesh() -> geo<mesh>` (и `empty_points()`) — явная нейтраль для `repeat`/`merge`; `mesh_line(count = 0)` оставить работающим.
- D3. `sweep`: задокументировать в §8 и в карточке `pgg_docs("builtin:sweep")` соответствие осей профиля и `profile_scale` при вертикальном пути (или добавить параметр `profile_up`). Сейчас это узнаётся кадром.
- D4. `bevel`: `width` — уже абсолютный; в `lib.parts.cbox` добавить `k_abs: f32 = 0` (абсолютная фаска, приоритет над `k`) и предупреждение в docstring про min-размер.
- D5. Диагностика E-код для «тернарник над несовместимыми geo» с подсказкой «используйте select / отдельные def» — чтобы ошибка сама вела к решению.

**Приёмка D:** `hexa_brick_face`/`hexa_brick_clock_face` сливаются в один def с `select`; корпусные тесты на `select`, `empty_mesh`, `sweep`-оси.

## 5. Этап E — процесс (в `AGENTS.md` «PGG» и rule A2, без кода)

- E1. **Правка общего def'а → рендер всех потребителей.** Перед правкой `grep -n "<def>(" resources/pgg` и список потребителей в ответ; после — по одному виду на потребителя (мансарда **и** шпиль для `hip_caps`/`tile_field`).
- E2. **Сравнение с референсной деталью в одном кадре.** Задачи вида «как у дома» (карниз, фаски, высота этажа) проверяются кадром, где обе детали видны рядом (`belt_junction`), а не двумя отдельными.
- E3. **Числа до кадра.** Если критерий выражается числом (равные зазоры, одинаковая высота, вынос больше квойнов на N см) — сначала `pgg_measure`/`bbox`, потом картинка.
- E4. **Новые грабли — сразу в `cheatsheet.md` §4** (одна строка), а не в память сессии; при правке ядра — ещё и в `implementation.md`.
- E5. **Виды — в `.views.json`**, а не в чат: любые координаты `target`, подобранные вручную и оказавшиеся полезными, сохраняются именованным видом в том же коммите.
- E6. **Коммит-единица — один визуальный эффект**: сессия показала, что «починил черепицу мансарды» и «сломал коньки» попали в один шаг; с контакт-листом (C1) регрессия видна до коммита.
