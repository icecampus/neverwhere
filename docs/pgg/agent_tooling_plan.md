# Улучшение инструментов отладки для агента — план работ

**Статус:** A1–A3, B1–B3, C1–C2 реализовано (2026-09-08); остальное — план. Объединяет предложения по PggTool/PggViewer и по MCP-серверу для итеративного цикла правок. Каждый пункт привязан к конкретному инциденту последних сессий, где агент упирался в инструмент и делал работу в обход (numpy вместо сэмплирования поля, `cmp` по OBJ вместо diff'а, `xvfb-run` с ручным подбором орбиты и `--shot-delay=14` вслепую).

## 0. Постановка

Главный пользователь PGG — кодинг-агент. Он не крутит модель мышкой и не ставит брейкпоинт: единственный способ **увидеть** результат — задать вопрос инструменту и прочитать ответ. Критерий качества инструментария — сколько вопросов агент может задать за один вызов, насколько ответ детерминирован и diffable, и сколько секунд длится цикл «правка → картинка + числа».

**Текущий цикл** (замерено на `cottage_mansard.pgg`, узел `house`):

| Шаг | Как сейчас | Время |
|---|---|---|
| проверка синтаксиса/типов | отдельный `PggTool check` (агент часто пропускает) | 50 мс |
| картинка | `xvfb-run PggViewer f --preview=house --preview-orbit=… --shot=… --shot-delay=14` | ~20 с (старт + полный прогон 16 с + слепая задержка) |
| нацелить камеру на деталь | нельзя (орбита вокруг bbox всего дома); обход — `--preview=door` без контекста | 2–3 итерации |
| числа по узлу | `PggTool run … --probe/--obj` — ещё один полный прогон, кэш не переживает процесс | 16 с |
| проверить «ничего не сломал» | `PggTool run --obj` ×2 + `cmp` | 2×16 с + ручной разбор |
| значения поля/SDF в точке | **нет** — переписывание SDF на numpy | ~час |
| здоровье меша (вырожденные грани, non-manifold) | **нет** в CLI — только внутри голден-тестов | 2 мин прогона `tower` |

Итого одна итерация — 30–60 с и 3–4 вызова инструментов; половина времени — повторные полные прогоны одного графа, потому что кэш (`MemoryCache`, §5.3 спеки) живёт только внутри процесса.

**Что уже есть и на что опираемся:** контракт пробников `path:inspector[param=value,...]` с инспекторами `schema · stats · coverage · table` (§9, E6); `PggTool run/check/fmt/ast/docs`; `PggViewer` с `--preview/--preview-orbit/--preview-highlight/--shot`, причём `--shot` читает кадр из GPU на всех бэкендах (`95e079a`: `glReadPixels` / readback drawable на Metal / backbuffer на D3D11) — offscreen-рендер не нужен; паттерн RPC-сервера `editor_rpc_server.cpp` (построчный JSON по TCP, команды на GUI-потоке) и MCP-обёртки над ним `tools/editor_mcp/server.py`.

## 1. Этап A — сервер `PggViewer --serve` и MCP `neverwhere-pgg` (главный множитель)

**Цель:** правка файла → один MCP-вызов → картинка нужного узла + его статы + диагностики, за секунды, по тёплому кэшу.

**Почему не обёртка над CLI:** подпроцессы на каждый вызов экономят только токены на командные строки. Выигрыш даёт **постоянный процесс**: один загруженный движок с `MemoryCache` (правка цвета ставней пересчитывает только хвост после `windows`, а не 16 с всего дома), один GL-контекст на сессию (нет старта Xvfb/окна на каждую картинку), диагностики до тяжёлого прогона.

### A1. RPC в PggViewer

**Статус: реализовано (2026-09-08).** Уточнения по ходу: `load{source}` — через temp-файл `tmp/pgg_rpc_source/src_N.pgg` (in-memory путь не понадобился: все потребители читают файл с диска); `render` — двухфазный (poll-фаза: опции + синхронный прогон; ответ из `frame()` после первого закоммиченного кадра с новой геометрией); CLI `--shot` с `--preview` без явного `--shot-delay` тоже по готовности кадра (явный `--shot-delay` — старое wall-time поведение); ёмкость сессионного кэша 4096, не 512 (cottage_mansard — ~2.2k кэшируемых binding'ов, LRU при 512 thrash'ил); измеренный эффект кэша честно таков: на беззонных графах тёплый прогон ≈ 0 (e4_sdf_rock), но cottage_mansard НЕ ускоряется (Debug `house`: 80.8 с холодный vs 101.4 с тёплый при 96 % hits) — фингерпринты зон repeat/foreach = 0 by design (E7), зональные binding'и кэшем пропускаются; закрытие этой дыры — отдельная работа за рамками A1; PNG — весь кадр окна (тот же `capturePng`, что у `--shot`), аргумент `size` у `render` двигает сплиттер превью-панели, а не ресайзит окно; `PggTool docs`/`writeObj` вынесены в `pgg::eval` (`docs_lookup`, `obj_export`) и разделены с RPC, заодно исправлен use-after-free qualified `docs`. При `--serve --no-ui` (или в `--smoke`) `render` отвечает ошибкой `no_frame_loop`.

- `PggViewer [file] --serve 127.0.0.1:9878` — TCP, построчный JSON, команды исполняются в `frame()` на GUI-потоке (как в редакторе). Работает и с окном (человек видит то же, что агент), и под `xvfb-run`/`--no-ui`.
- Команды: `load {path | source, lib_roots}` → диагностики (код, строка, сообщение, путь binding'а) без прогона; `params {name: value}`; `render {node, orbit?, target?, highlight?, shading?, colors?, size?}` → PNG (путь или base64) + статы узла (kind, pts/tri, bbox, группы с числами граней); `probe {spec}` → записи инспекторов; `export {node, obj_path}`; `docs {symbol}`; `status`.
- **Захват по готовности, не по таймеру.** Сейчас `--shot` срабатывает по `--shot-delay` (wall-time). В сервере: команда `render` ставит цель превью → после завершения `runPreview` и первого отрисованного кадра с новыми параметрами — readback тем же `capturePng` → ответ. `--shot-delay` остаётся как override для CLI.
- Кэш прогона (`RunParams.cache`) — один на сессию, переживает `load` того же файла: перезагрузка после правки пересчитывает только изменившиеся binding'и.
- Файлы: `src/apps/PggViewer/main.cpp` (frame/serve), новый `src/apps/PggViewer/ViewerRpcServer.h/.cpp` (по образцу `editor_rpc_server.cpp`), без новых зависимостей.

### A2. Нацеливание камеры

**Статус: реализовано (2026-09-08).** Уточнения по ходу: top-вид — это pitch **+90°** в конвенции орбиты вьювера (`eye = center + dir(yaw,pitch)·distance`: +90 ставит камеру НАД целью; плановое «pitch −90» ставило бы её под сцену), up на полюсе — `(0,0,−1)` (фасад остаётся внизу плана); полувысота орто-фруста — `radius·1.3·fitZoom` (множитель, не делитель — fitZoom это множитель дистанции: больше zoom = дальше камера = больше видно), `distance=` в CLI не стал отдельным флагом (есть у `setTarget` в API и выводится как `camera.distance`; третий компонент `--preview-orbit` закрывает zoom); `group:` без домена матчится по голому имени (неоднозначность → первая по сортировке + warn); `binding:` резолвится один раз на `load` (зональные графы тёплым кэшем не ускоряются, повторный pull на каждый rebuild был бы полной ценой прогона); wire — отдельный pos-only шейдер flat-color + line-пайплайн с z-bias в клип-пространстве (portable замена polygon offset), без домешивания в основной шейдер; в ответе `render` — `camera:{center,radius,distance}` фактического состояния.

- `target` в `render` и `--preview-target=` в CLI: `x,y,z` | `group:<имя>` | `binding:<путь>` — центр орбиты и fit по bbox цели, остальная сцена остаётся. Плюс `fit=all|target`, `distance=`, `ortho=front|side|top` (ортопроекции сильно упрощают чтение размеров), `wire=on`.
- Файлы: `GeometryPreview.h/.cpp` (камера), `main.cpp` (флаги).

### A3. MCP-обёртка

**Статус: реализовано (2026-09-08).** Уточнения по ходу: автоподнятие ищет бинарь в порядке env `NEVERWHERE_PGG_VIEWER` → `_int_clion_release` (Release) → `_int_clion` (Debug) → `_intermediate_64` (Debug) — Release предпочтителен, прогон коттеджа ~4 с против ~80 с в Debug; stdout/stderr viewer'а — в `tmp/pgg_viewer_serve.log` (наследовать stdio нельзя — сломает MCP-транспорт); таймаут клиента 600 с (render отвечает только после закоммиченного кадра). Контракт — `docs/pgg/viewer_rpc.md`.

- `tools/pgg_mcp/server.py` по образцу `tools/editor_mcp/server.py`; запись `neverwhere-pgg` в `.mcp.json` (Linux/macOS: `sh`, Windows: `powershell`) — поднимает PggViewer с `--serve`, если порт не отвечает.
- Инструменты: `pgg_load`, `pgg_params`, `pgg_render`, `pgg_probe`, `pgg_export`, `pgg_docs`, `pgg_status`. Ответ `pgg_render` — картинка **и** числа в одном сообщении: картинка без чисел бесполезна, числа без картинки тоже.
- Документация: раздел в `docs/mcp_servers.md`, абзац в `implementation.md`, короткая строка в `AGENTS.md` («Инструменты»).

**Приёмка A:** цикл «правка `cottage_mansard.pgg` → `pgg_render(house, target=group:lamp)`» ≤ 5 с на тёплом кэше (первый прогон — как сейчас); невалидный файл — ответ с диагностиками за < 100 мс без прогона; смоук `PggViewer --serve … --smoke` в тестах приложения; `docs/pgg/implementation.md` обновлён.

## 2. Этап B — пробники для полей, SDF и здоровья меша

**Инцидент:** `mc_thin_shell_slivers.md` — чтобы увидеть, что «оболочка 0.12» на торце на самом деле стенка 1 см, а грань лежит ровно на узле решётки, потребовалось сэмплировать поле в точках; PggTool этого не умеет, автор брифа ушёл по ложной гипотезе, а корректный ответ занял бы одну команду. Там же: 12 % треугольников нулевой площади в оболочке крыши никто не видел, а 6 non-manifold рёбер от первой версии фикса всплыли только в двухминутном голден-тесте.

Все инспекторы — расширение существующего контракта `path:inspector[params]`, доступны и в `PggTool run --probe`, и в `pgg_probe` сервера; реализация — `engine.cpp`/`probe.cpp`, тесты — `probe_test.cpp`.

**Статус B1–B3: реализовано (2026-09-08).** Уточнения по ходу: vec-значения параметров пишутся **в скобках** — `at=(0,1,3.425)` вместо плановой `at=0,1,3.425` (иначе сплит по запятым неоднозначен; зафиксировано в спеке §9.6, сплит — по запятым верхнего уровня с учётом скобочной глубины, `make_rock[1]:sample[at=(0,0,0)]` разбирается правильно); geo-таргет `sample`/`slice` — **псевдо-знак** по нормали ближайшего треугольника (готовый оракул `MeshBvh::closest`, тот же, что у `sdf_from_mesh`), пометка в заголовке записи, не unsigned; **`slice` без PNG** (в pgg-lib нет stb, ASCII/CSV закрывают инцидент — `format=png,out=…` не реализован); `check`: **boundary рёбра и число компонент — информативные строки, в `issues` не считаются** (boundary — норма для открытых мешей, components>1 — норма для fracture/мержей); `limit` теперь валиден и для `check` (списки индексов), `aggregate` ограничен связкой schema/stats/coverage. Контракт — спека §9.6, реализация — `implementation.md`. Живая приёмка: репрокейс `mc_thin_shell_slivers.md` — `shell:slice[axis=z,at=3.425,step=0.25]` печатает треугольник щипца, на 3.40/3.45 — пусто; на текущей крыше `roof_all:check` → degenerate 13, needles 18610 (6.0 %), components 820, boundary 39, `multi_gable[0].deck:check` → degenerate 19 (float-нулевая площадь при edge_min 4.5e-08 — микрорёбра после побитовой сварки), needles 5.6 %, nonmanifold 0 — наблюдение зафиксировано, геометрия крыши сознательно не правилась.

- **B1. `sample`** — значение в точках: `shell:sample[at=0,1,3.425]`, несколько точек через `;`, профиль `sample[from=…,to=…,n=41]`. Для `sdf` — поле; для `geo` — ближайшая точка/грань и расстояние (для мешей — псевдознак `sdf_from_mesh`, помеченный). Вывод `x y z value` построчно, `%g`.
- **B2. `slice`** — срез поля: `slice[axis=z,at=3.425,step=0.25]` → ASCII-карта (`#` внутри, `.` снаружи; для агента текст в контексте важнее PNG), `format=csv` — значения, `format=png,out=…`. Границы — conservative bbox или `bounds=`.
- **B3. `check`** — здоровье меша: вырожденные грани (нулевая площадь / повторные индексы), non-manifold и boundary рёбра, изолированные точки, NaN/inf в `@P/@N/@Cd`, компоненты связности и несогласованная ориентация по компонентам, min/median ребра, доля «иголок» (`warn_aspect=20`).
- **B4. `lattice`** — решётка `mesh_from_sdf` глазами автора: `shell:lattice[voxel=0.05]` печатает начало/шаг/размеры и предупреждает про осевые грани примитивов DAG ближе 0.05·voxel к плоскости решётки и пары параллельных граней на расстоянии < 2·voxel (кандидат на пропадание/рвань). Та же эвристика — как W-код в `check`, когда в графе есть `mesh_from_sdf`.
- **B5. `table[where=<поле>]` и `find[where=…]`** — отфильтрованные строки (предикат — обычное поле PGG, парсер и eval уже есть) и быстрый ответ «сколько и где» (count, bbox подмножества, группы).
- **B6. `--eval '<expr>' --on <binding>`** — вычислить произвольное поле в контексте файла на заданной геометрии и прогнать через инспекторы (синтетический binding поверх `FlatProgram`, семантика `set(on, "tmp", expr)`); закрывает «какой разброс у этого шума на самом деле» без правки файла.

**Приёмка B:** для каждого инспектора — команда из инцидента и её ожидаемый вывод фиксируются тестом; `slice` на репрокейсе из `mc_thin_shell_slivers.md` показывает треугольник щипца на `z = 3.425` и пусто на `3.40/3.45`; `check` на нём же до фикса `5cacc1b` дал бы `degenerate 15458`, после — малое число (фактически на 2026-09-08: `roof_all` → 13, SDF-настил `deck` → 19 — float-нулевая площадь на микрорёбрах, индекс-вырожденных нет; см. статус B1–B3 выше); контракт инспекторов — в §9 спеки, реализация — в `implementation.md`.

## 3. Этап C — сравнение прогонов и голдены

**Инцидент:** каждая декомпозиция `cottage.pgg` проверялась `cmp` двух OBJ; при отличии `cmp` говорит только «байт N». Фикс фазы решётки означал ручное переснятие 40 литералов в `*_test.cpp` скриптом по gtest-выводу.

**Статус C1–C2: реализовано (2026-09-08).** Уточнения по ходу: ΔP-строка — `ΔP max <X> (point #i, group g)` + `ΔP mean <Y>` (в плановом примере был только `(vines)`; индекс точки добавлен — агенту он нужнее всего); g — первая по сортировке faces-группа **стороны b** (новой геометрии), покрывающая инцидентные грани точки максимума, `-` если ни одной; ΔP считается только при kind=mesh с обеих сторон и равном числе точек (mean — f64). sdf/field-выходы — `skipped (no structural fingerprint)` и в вердикт не входят (структурного fp у них нет by design, иначе self-diff коттеджа с sdf-выходом никогда не был бы identical). Хранимый `@N` фигурирует как `+attr/-attr N(vec3/normal,points)` — иначе добавление/снятие compute_normals давало бы «пустую» таблицу при разном fp. Baseline-парсер пропускает все не-fingerprint строки — `--fingerprint > a.fp` годится как baseline без фильтрации. Логика сравнения — `pgg::diffGeo`/`formatGeoDiff` в `eval/geo_diff.{h,cpp}` (lib без json-зависимости), `--json` собирается в PggTool через `nlohmann::ordered_json` (у PggTool теперь линковка `nlohmann_json::nlohmann_json`, зависимость уже была в vcpkg.json). Exit-коды diff: 0 identical, 1 различия/ошибки прогона, 2 usage/io. **Не сделано в этом заходе:** `pgg_diff` в сервере против снимка предыдущего `load` (пункт C2 «в сервере» — отложено вместе с C3/C4); сравнение `~attr` при смене типа/typeinfo без смены имени (сейчас такое видно только по разному fp); `--param`/`--threads` у diff.

- **C1. `run --fingerprint`** — per-output хеши позиций/топологии/атрибутов отдельно (fingerprint в ядре есть — кэш §5.3; надо только вывести). `--json` на `run` заодно (выходы, пробники, диагностики — как у `check`).
- **C2. `PggTool diff a.pgg b.pgg [--output …]` / `diff --baseline <fp>`** — counts, bbox, появившиеся/исчезнувшие атрибуты и группы; при равном числе точек — max |ΔP| по сопоставленным точкам с именем группы (реальный случай: `ΔP max 0.0008 (vines)`, найденный вручную). В сервере — `pgg_diff` против снимка предыдущего `load`.
- **C3. Голдены-файлы** — `src/tests/pgg/goldens/<name>.fp` (текст, diffable) вместо литералов; тест сравнивает fingerprint; `PggTool run --update-goldens` переснимает. Снижает цену любого честного изменения численного профиля.
- **C4. `--obj --obj-split-groups`** (`house.roof.obj`, …) и `--obj-color=check` (вырожденные/non-manifold/boundary — цветом) — локализация проблемы любым внешним просмотрщиком.

**Приёмка C:** `PggTool diff` на двух версиях `cottage.pgg` до/после выноса `lantern` печатает `identical`; на `5cacc1b`^..`5cacc1b` — таблицу сдвигов по SDF-выходам; голдены `sphere/rock/wall/fracture/tower` переведены в файлы, тесты зелёные.

## 4. Этап D — ошибки и справка

**Инцидент:** ложный E302 при `value(@wid, on = a)` внутри def-аргумента искался полдня — сообщение не говорило, *на какой* геометрии проверяется и *откуда* пришло поле. Отдельно — «спека в контексте»: агент держит в голове весь §8, `docs <file> <symbol>` работает только для def'ов файла.

- **D1.** В сообщениях E302/E204/E606 — путь binding'а, на котором проверяется, и цепочка инлайнинга (`field consumed by set_position on bx[0].out ← arg w of bx ← value(@wid, on = p1)`).
- **D2. `check --explain E302`** — карточка кода: смысл, типичные причины, пример с фиксом; генерируется из таблицы кодов §12 спеки, не дублируется руками.
- **D3. `docs builtin <name>`** (`docs builtin clip`) — сигнатура + абзац из §8 + один пример; `docs builtins [--group topology|sdf|fields]` — список сигнатур по строке. В сервере — `pgg_docs`. Это то, что агент хочет вместо чтения 1000-строчной спеки: короткий точный ответ «как называется параметр и какой дефолт».

**Приёмка D:** регресс `ZoneForeach.ValueAggregatorInsideFieldBindsToOnGeometry` в варианте «до фикса» печатает цепочку инлайнинга; `docs builtin` покрывает все builtin'ы из `builtins.cpp` (тест на полноту).

## 5. Этап E — профилирование

`house` считается 16 с; агент не знает, где. `run --profile` (и `pgg_status` сервера) — таблица по binding'ам: время, число field-eval'ов, cache hit/miss, объём геометрии на выходе, top-20 по времени; `bake_ao`/`mesh_from_sdf`/`realize` — отдельными строками. Данные частично есть (`bindingFieldEvals`, счётчики кэша) — не хватает вывода.

## 6. Что не делаем

- REPL/интерактив: агент работает вызовами — нужны идемпотентные команды с полным ответом, не сессия команд (сервер держит **состояние**, но каждая команда самодостаточна).
- Графический дебаггер узлов в PggViewer — вью для человека.
- Свой формат вместо OBJ — нужны расширения экспорта (группы, цвета), не замена.
- Offscreen FBO-рендер ради скриншотов — не нужен, readback с swapchain уже есть на всех бэкендах.
