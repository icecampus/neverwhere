# PggViewer RPC + MCP (`neverwhere-pgg`)

_Контракт агентского RPC вьювера (этапы A1/A3 из `docs/pgg/agent_tooling_plan.md`). Правя соответствующий код (`src/apps/PggViewer/ViewerRpcServer.cpp`, `main.cpp`, `tools/pgg_mcp/`), обновляй **этот** документ._

`PggViewer [file] --serve[=host:port]` поднимает TCP RPC-сервер на `127.0.0.1:9878` (построчный JSON, команды на GUI-потоке через `poll()` в `frame()`; занятый порт — ошибка в лог, живём без сервера). Реализация: `src/apps/PggViewer/ViewerRpcServer.h/.cpp` (транспорт, диспетч) + `registerPggViewerRpcHandlers` в `src/apps/PggViewer/main.cpp` (команды). Конверт — как у редактора (`docs/editor_rpc.md`): запрос строка `{"op":"…","args":{…}}`, ответ строка `{"ok":true,"data":{…}}` | `{"ok":false,"error":{"kind","message"}}`.

Операции:

- **Сессия:** `ping` → `{pong, app, protocol}`; `status` → `{file, params, cache:{size,capacity,hits,misses}, preview:{target,has_value}, uptime_s}`.
- **Файл и параметры:** `load {path|source, lib_roots?}` — `source` пишется в `tmp/pgg_rpc_source/src_N.pgg` (mkdir -p) и дальше идёт как `path`; ответ — статическая проверка без прогона (closure → expand → typecheck): `{diagnostics:[{code,line,col,warning,message}], has_errors, ms, path}`, невалидный файл отвечает за миллисекунды. `params {name:value}` — те же поля, что панель Params и `--param` (массив → вектор `(x, y, z)`), неизвестные имена — в `unknown` ответа.
- **Прогон:** `render {node, out?, orbit?, highlight?, shading?, colors?, size?, target?, fit?, ortho?, wire?}` → `{path, width, height, node, stats:{kind,pts,tri,bbox,groups,ms}, diagnostics, camera:{center:[x,y,z],radius,distance}, cache:{hits,misses}}` (`diagnostics` — предупреждения прогона; прогон без значения — ошибка `run_failed`, прогон со значением, но с E-диагностиками (рантаймовый E609 в глубине графа отдаёт частичный меш) — ошибка `run_errors` с их списком: картинка половины сцены с ok=true хуже, чем отсутствие картинки); `probe {spec}` (`"path:inspector[params]"`) → `{records:[{origin,path,inspector,text}], diagnostics, has_errors, ms, cache}`; `export {node, obj_path}` (OBJ, instances — через realize, sdf — ошибка `no_geometry`); `docs {symbol}` → `{symbol, signature, docstring}` (qualified тоже, ошибка `not_found`).

  **Камера render (A2):** `target` — строка `"x,y,z" | "group:<имя>" | "binding:<путь>"`: центр орбиты и (при `fit=target`) fit по цели, остальная сцена остаётся в кадре по fit-дистанции цели. `group:` берёт bbox группы из per-group bbox'ов свежего прогона (имя с доменом `"faces:roof"` или голое `"roof"` — суффикс-матч, неоднозначность → первая по сортировке + warn); `binding:` делает отдельный pull пути по тёплому кэшу и берёт bbox его геометрии (резолвится один раз на load — зональные графы кэшем не ускоряются; адресуются только top-level binding'и, инстансы и `<instance>.<local>` — локалы заинлайненного def'а, вроде `door` внутри `assemble`, недоступны); точка `x,y,z` — центр орбиты при scene-радиусе. **Неразрешённый target — ошибка `target_unresolved`** с причиной и списком групп превью (не тихий откат на `fit=all` с не той картинкой); target при этом сбрасывается, следующий `render` без него не застревает. В CLI тот же случай — warn + откат на `fit=all`. **Авто-ракурс:** если в этом `render` не задан `orbit`, yaw поворачивается так, чтобы камера стояла со стороны цели относительно центра сцены (`faceTargetFromOutside`: `yaw = atan2(dx, dz)` вектора центр сцены → центр цели; цель у центра сцены, < 0.1·радиуса по горизонтали — yaw не трогается; в орто-видах не применяется) — иначе цель на фасаде снималась изнутри дома через заднюю стену. Явный `orbit` (или `--preview-orbit` в CLI) авто-ракурс отключает. `fit` — `"all"|"target"` (дефолт: `target`, если задан `target`, иначе прежний режим). `ortho` — `"front"|"side"|"top"|"off"`: ортопроекция по оси со снапом ракурса (front = камера на +Z, side = на +X, top = сверху +Y; yaw/pitch пользователя сбрасываются в предустановку, мышь потом крутит как обычно). `wire` — bool: тёмный line-list рёбер поверх шейдинга (dedup по рёбрам, мелкий z-bias вместо polygon offset). Без `target` в вызове прежний target **сохраняется** (как orbit/highlight); снять — `target:""` или `fit:"all"`. `camera` в ответе — фактическое состояние после применения: `center` (центр орбиты — у group-target центр bbox группы), `radius` (радиус активного fit), `distance`.

Грабли: `render` **двухфазный и синхронный** — прогон в poll-фазе блокирует frame loop на всё время, ответ приходит из `frame()` после первого закоммиченного кадра с новой геометрией; `out` по умолчанию `tmp/pgg_rpc_shots/shot_N.png`, PNG — весь кадр окна (`size` двигает сплиттер превью-панели, не ресайзит окно); параллельный render — ошибка `busy`. render требует UI-режим: с `--no-ui`/`--smoke` отвечает `no_frame_loop`. `probe`/`export` тоже синхронные. macOS: poll() живёт в frame(), поэтому при залоченном экране кадры не тикают и RPC стоит целиком (idle sleep/App Nap вьювер давит сам через `beginActivity`, лок экрана это не лечит). Сессионный `MemoryCache` (4096) переживает `load` того же файла: правка инвалидирует только downstream — но зоны repeat/foreach кэшем пропускаются by design, поэтому тяжёлые зональные графы (cottage_mansard) тёплым прогоном не ускоряются.

MCP-обёртка: серверы `neverwhere-pgg` (macOS/Linux, sh) / `neverwhere-pgg-win` (powershell) в `.mcp.json`, код — `tools/pgg_mcp/` (FastMCP stdio, инструменты `pgg_status/pgg_load/pgg_params/pgg_render/pgg_probe/pgg_export/pgg_docs`, ответ RPC as-is; лаунчеры `tools/run_pgg_mcp_server.{sh,ps1}`). В отличие от editor MCP, **viewer поднимается автоматически**: если порт 9878 не отвечает, ищется бинарь (env `NEVERWHERE_PGG_VIEWER` → `_int_clion_release/.../Release/PggViewer` → `_int_clion/.../Debug/PggViewer` → `_intermediate_64/.../Debug/PggViewer`; предпочтение Release — он в разы быстрее), `Popen([viewer, "--serve"])` (на Linux без DISPLAY — `xvfb-run -a`), ожидание порта до 30 с; лог viewer'а — `tmp/pgg_viewer_serve.log`. Типовой цикл: `pgg_load` → `pgg_render` → чтение PNG файлом → `pgg_probe` → правка файла → `pgg_load` снова (тёплый кэш).
