# Генерация хайграунда: исследование подходов (июль 2026)

Сводка исследования по теме «как генерировать поднятую 3D-землю (плато + отвесные
стены) в изометрическом 2.5D-редакторе на вершинной сетке». Собрано из пяти
направлений: локальные референсы репозитория, игровые клифф-системы
(WC3/SC2/OpenTTD/OpenRCT2), marching squares / dual grid, процедурные скалы и
террасы, сортировка 2.5D-геометрии без z-buffer.

Связанные документы: `docs/VERTEX_CENTRIC_LANDSCAPE.md`, `docs/TECHNICAL_STACK.md`,
`docs/reference/README.md` (библиотека бумаг).

## Главный вывод

**Никто в индустрии не триангулирует контур поднятой области в рантайме.**
Обе полюсные стратегии:

1. **Blizzard RTS (WC3, SC2):** per-tile pattern matching — по конфигурации
   высот 4 углов тайла выбирается готовый, заранее сваренный кусок геометрии
   (WC3: ~94 модели; SC2: именование по буквам высот углов `BBDC_00`). Сетка
   только *индексирует* библиотеку. Верх — часть куска, стыков и триангуляции
   в рантайме не существует.
2. **Спрайтовые изометрические движки (OpenTTD, OpenRCT2):** вертикальные
   стены строятся **независимо на каждой грани клетки** (сравнение высот двух
   своих углов с двумя соседними), столбцом повторяющихся сегментов +
   filler-варианты для неровного контура. Сортировка бесплатна: сегмент стены
   принадлежит клетке и сортируется в её painter-позиции.

Наш текущий путь (CGAL union + CDT по глобальному контуру) алгоритмически
корректен и фаззером подтверждён; «плохой визуал» — следствие не алгоритма
триангуляции, а (а) формы контура (лесенки из целых клеток), (б) раздельной
генерации верха и стен, (в) текстурирования стен, (г) painter-сортировки.

## 1. Игровые клифф-системы

### Warcraft III (вершинная сетка — наш ближайший аналог)

- `war3map.w3e`: сетка tilepoints `(N+1)×(N+1)` = наши вершинные ноды. У
  tilepoint: плавный `ground_height` + дискретный `layer_height` (уровень
  клиффа) + флаг ramp + текстуры. Две ортогональные системы высот.
- Для каждого тайла: 4 угла → `base = min` → буквы `'A'+diff` в порядке
  TL,TR,BR,BL → имя модели `Cliffs<XXXX><var>.mdx` (~94 модели, 3 вариации).
- **Pinch (два противоположных угла подняты) поддержан**: модель `CliffsBABA`
  — проблема закрыта артом, а не алгоритмом.
- Верх клиффа — часть модели, его край = сетка тайлов → стык идеален по
  построению. Верх текстурируется ground-текстурой клиффа (приоритет:
  cliff > blight > ground в Moore-окрестности).
- Плавный heightmap натягивается на клифф-модель билинейной деформацией
  угловых вершин.
- Источники: https://github.com/stijnherfst/HiveWE/wiki/war3map.w3e-Terrain ,
  https://raodaozao.net/2018/07/16/blog-747/

### StarCraft II

- Клифф-кусок = модель 200×200 units = 2×2 terrain-клетки; углы буквами
  A/B/C/D (CCW от bottom-left), ramps Q/R/S; 4 вариации на паттерн.
- **Стандартизация профилей** — ключ к отсутствию швов: внешние вершины
  каждой модели в фиксированных позициях; все стороны `B-C`/`C-B` идентичны
  во всех моделях сета; сторона `B-B` совпадает с террейн-сеткой.
- **Pinch запрещён редактором** (кисть принудительно распространяет уровень) —
  легитимный дешёвый выход вместо решения проблемы.
- **Текстурирование: tri-planar world-space mapping** — «no seams, no need
  for UVs». **Vertex color alpha** пропускает terrain-материал на стыке:
  полоска террейн-меша с градиентной прозрачностью «наплывает» на скалу.
- Источник: https://mapster.talv.space/star-tools/Appendix_Cliffs.html

### OpenRCT2 (самый релевантный для painter-рендера)

- Тайл: `baseZ` + 5-битный slope (4 бита поднятых углов + diagonal flag).
- Стена per-edge: `ViewportSurfaceDrawTileSide{Bottom,Top}` — сравнение своих
  2 углов с 2 соседними вдоль грани; **столбец edge-спрайтов** от min(сосед.)
  до min(своих), любая высота из повторов 16-px спрайта; filler-спрайты
  (offset 1/2 — наклонный верх, 3/4 — наклонный низ) закрывают неровный
  контур.
- Сортировка: edge-спрайты принадлежат тайлу и рисуются в его
  painter-позиции (top-грани — attach к спрайту поверхности).
- Smoothen-edge: masked-спрайт с паттерном соседней текстуры на шве (дизер).
- Источники: https://github.com/OpenRCT2/OpenRCT2/blob/develop/src/openrct2/paint/tile_element/Paint.Surface.cpp

### OpenTTD

- Углы общие между тайлами → поверхность непрерывна, «разности высот между
  тайлами» нет как сущности; вертикальные стены — только foundations под
  постройками (`DrawFoundation`, 4 блока спрайтов по видимости NW/NE граней).
- Источник: https://github.com/OpenTTD/OpenTTD/blob/master/src/slope_type.h

### RPG Maker A4 (урок про стык верх/стена)

Возвышенность = пара autotile-систем: «ceiling» (верх) визуально **нависает
над стеной** — стык скрыт перекрытием, а не геометрической точностью.

## 2. Marching squares, dual grid, триангуляция верха

- Наш `boundaryLoops` (land-on-left walker + pinch-split) — канонический
  подход: для бинарных узлов неоднозначность 5/10 неразрешима (asymptotic
  decider вырождается в фиксированное правило), важно лишь **единое правило
  для стен и заливки** — у нас обеспечено общими петлями.
- Классификация петель outer/hole по ориентации (Suzuki–Abe border following)
  — для заливки дырок без CGAL, если захотим от него уйти.
- Триангуляция верха: earcut (быстрый, хрупкий к self-touching — у нас уже
  разрезано), CDT (текущий, гарантирует границу = констрейнтам — правильный
  паттерн), libtess2/monotone, polypartition. Если визуал не нравится —
  менять надо **форму контура**, не триангулятор.
- **Dual grid**: данные на узлах, рендер-сетка смещена на полклетки, каждый
  display-тайл = 4 бита углов → 16 спрайтов со скруглёнными углами. Наш
  per-cell top (e2b7897) — это фактически dual-grid рендер. Для стен не
  применим.
  Источники: https://github.com/pablogila/TileMapDual ,
  https://www.boristhebrave.com/2022/01/03/resolving-ambiguities-in-marching-squares/

## 3. Процедурные скалы и террасы

### Straight skeleton + офсеты (главная находка; CGAL уже подключён)

- `create_interior_skeleton_and_offset_polygons_2` — офсет-полигоны на любой
  дистанции `t`, strictly-simple, **острые углы сохраняются**. Серия офсетов
  `t1<t2<...` = готовые ступени террасы; скелетный узел хранит `time` =
  дистанцию до контура = бесплатный clearance для клампа displacement-шума.
- **Raybevel** (Tyler Morgan-Wall): 3D-меш из скелета — roof (высота узла =
  его time) + arbitrary bevel-профиль (узлы на рёбрах скелета с высотами);
  bevel `"step"` = зиккурат. Рецепт топологических сплитов при распаде
  офсет-полигона: поиск от локальных максимумов (пиков крыши).
  https://www.tylermw.com/posts/rayverse/raybevel-introduction.html
- Caveat: при почти-коллапсирующих рёбрах нужен exact constructions kernel.
- Применение к нам: (1) мелкий inset региона = фаска, согласованная со
  стенами (закрывает текущий зазор верх/стены); (2) серия inset'ов = террасы;
  (3) time скелета = clearance для шума смещения стен.

### Деформация стен под скалу

- **World-space 3D noise = бесшовность по построению** (GPU Gems 3 ch.1:
  `density = −ws.y + Σ octaves`, domain warp). Arc-length noise вдоль контура
  как техника не встречается — индустрия сэмплирует по мировой позиции (у нас
  уже так, walls.cpp world-coherent) или варит профили заранее (SC2).
- **SCAVENGER** (стилизованные каньоны): cellular noise (булыжники) + Simplex,
  растянутый по X/Z (strata-бороздки); **нормали НЕ пересчитываются** после
  displacement — детальный силуэт + плоский шейдинг; кромка верха «рваная»
  через blue-noise alpha-cutoff. Дешёвые приёмы именно под рисованный вид.
  https://blog.roytheunissen.com/tag/shader/
- Paris 2020 (rock fracturing, порт у нас в `src/refs/`): smooth-intersection
  полуплоскостей `max(fA,fB) − R·k³/6`, gradient warp с triplanar-весами —
  идеи переносимы, сам SDF/MC-пайплайн — нет (3D-поле, минуты на сцену,
  несовместимо с painter-рендером).
  NB: вердикт писался про Paris-2020. Позже в CliffFieldPlayground появился
  свой scalar-field + surface nets конвейер (~1.6 с на поле, watertight,
  z-buffer вместо painter) — другая весовая категория; сейчас он живёт в
  `highground_core` (`cliff_field.h`/`surface_nets.h`) и как кисть «Cliff 3D»
  в TileShapePlayground, см. `docs/TECHNICAL_STACK.md`.

### Текстурирование стен

- **Triplanar** — стандарт: проекции по осям, веса `|nᵢ|^k`; UV для стен не
  нужен вообще. У нас `Vertex::uv` для Wall зарезервирован — слот свободен.
  Для почти вертикальных стен хватит двухплоскостного варианта.
- Альтернатива: arc-length UV (`u` = длина дуги вдоль контура, шов один на
  дальней стороне плато).

## 4. Сортировка 2.5D без z-buffer

- **Эталон:** мировой AABB на примитив → попарное сравнение по разделяющим
  осям → граф «позади» → топосорт (Mazebert/as3isolib/Filmation;
  формально — Shaun Lebron, https://shaunlebron.github.io/IsometricBlocks/).
  Скалярный ключ `x+y+k·z` работает только для одноклеточных объектов — наши
  рукава покрывают диапазон глубин, это принципиальное ограничение текущего
  `Primitive::depth`.
- **Циклы перекрытий** (painter's dilemma) — фундаментальны: Tarjan SCC +
  разрез примитива/клип-регион (Shaun Lebron), удаление минимального числа
  рёбер (River City Ransom: Underground).
- **OpenTTD:** AABB + SSE separating-axis, без детекции циклов; глитчи лечат
  авторингом боксов (`bb_offset`, thin slices нулевой толщины);
  `StartSpriteCombine` — неделимая группа спрайтов в одном боксе.
- **OpenRCT2:** тот же separating-axis, жадная перестановка (не топосорт),
  debug-флаг stable sort; стены принадлежат клетке.
- **Unity Z-as-Y:** скалярный ключ `y + k·z`, трекер полон багов на
  мультиклеточных спрайтах.
- **Z-buffer:** современная практика — настоящая 3D-геометрия + ортокамера.
  Ломается только полупрозрачность (лечится alpha cutout + z-write, depth
  prepass). Для нашего highground-слоя (непрозрачные стены+верх, swapchain
  уже DEPTH_STENCIL, пайплайны с `SG_COMPAREFUNC_ALWAYS` + `write=false`,
  `Params::sortPrimitives=false` уже предусмотрен) — включение depth = смена
  двух полей в пайплайне. Убирает целый класс проблем сортировки рукавов.

## 5. Стыковка верха со стенами — промышленные паттерны

1. **Shared vertices по построению (WC3):** верх и стена делят вершины — у
   нас это boundary-first контракт; усиление — делать displaced-контур общим
   входом и для экструзии стен, и как constraint для CDT верха.
2. **Skirt (geometry clipmaps):** юбка верха плато вниз на 2–4 px закрывает
   микрощель у верхнего края стены без побайтового совпадения контуров.
3. **Fade-кромка (SC2):** полоска верха с градиентной альфы поверх кромки
   стены (требует blending; для непрозрачного слоя избыточно).
4. **Нависание верха (RPG Maker):** верх нарочно рисуется шире стены и
   перекрывает её кромку.

## 6. Локальные активы (что уже есть в репо)

- `docs/reference/papers/` — Paris 2019 (terrain amplification), Paris 2020
  (implicit blocks), Peytavie 2009 (Arches), Galin 2019 STAR (обзор) и др.
  Переносимы идеи: triplanar gradient warp, smooth-min фаски, presence-
  критерии «деталь только на крутых стенах», strata-по-высоте, domain-warped
  контур. Сам SDF/MC-пайплайн не переносим.
- `src/refs/aparis69-rock-fracturing-ref/` — рабочий порт (MIT) с
  `rock_scene/`: macro-форма + пристеночная полоса + tile-replication со
  сшивкой границ (`sampleTileWithNeighborBlend`) — экспериментальный стенд
  для визуальных гипотез.
- `prototypes/blender/` — визуальные референсы стен (Rock_Gen_2.0: convex
  hull кластеров как примитив скалы; наши clifs_*.blend).
- Свежий PoC «клиффы из heightmap без CSG»:
  https://github.com/aevns/cliff-terrain-prototype

## 7. Рекомендации (по соотношению цена/эффект)

1. **Z-buffer для highground-слоя** — убирает класс «стены за/перед верхом»
   и циклы рукавов; инфраструктура готова (DEPTH_STENCIL swapchain, флаг
   `sortPrimitives`). Дисциплина проходов: highground с depth-write первым.
2. **Straight skeleton офсеты** (CGAL уже есть): фаска на петлях перед
   триангуляцией (стык верх/стены), террасы серией inset'ов, clearance из
   `time` скелета для клампа шума. Одна структура закрывает три задачи.
3. **Triplanar для стен + flat normals + blue-noise кромка** (SCAVENGER) —
   дешёвый визуальный скачок под рисованный стиль; UV стен не нужен.
4. **Юбка 2–4 px на верх плато** — страховка от микрощелей поверх п.2.
5. **Форма контура, не триангулятор:** если «лесенки из клеток» не нравятся —
   Chaikin-сглаживание петли до развилки на стены/верх (общий сэмплинг → стык
   идеален), либо per-tile pattern-библиотека à la WC3/SC2 (16 паттернов,
   геометрия строится офлайн хоть тем же CGAL, профили стандартизованы).
   Второе — индустриальный мейнстрим и гарантированное качество, но меняет
   архитектуру с «генерации» на «сборку из кусков».
6. **Не брать в продакшен:** implicit/SDF/MC-пайплайн (несовместим с
   painter-рендером и пиксельной читаемостью 128×64), арки/нависания,
   arc-length noise вдоль контура (вместо — world-space sampling, уже есть).

## Пустые направления (честно)

- Painter-sort клиффов вне tile-движков не исследован (у всех z-buffer).
- Songs of Conquest / Against the Storm / AoE2 — технических разборов
  террейна публично нет.
- Внутренние сортеры SC1/SC2/Diablo2 — закрытые движки.
