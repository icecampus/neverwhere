# Tile Resolution: Blob 47 vs Vertex-Centric

## Источник

[Blob Tileset (cr31.co.uk)](https://www.boristhebrave.com/permanent/24/06/cr31/stagecast/wang/blob.html) — подмножество из 47 уникальных тайлов из полного набора 256 (2-edge + 2-corner Wang tiles).

## Два подхода

### Blob 47 (tile-centric)

- Данные хранятся на сетке `(2W+1) x (2H+1)`: tile centers + edge midpoints + corners
- Каждый тайл описывается **8 битами**: 4 ребра (N/E/S/W) + 4 угла (NE/SE/SW/NW)
- Полный набор: 2^8 = 256 комбинаций, blob-ограничение ("угол заполнен => оба смежных ребра заполнены") отсекает 209, остаётся 47
- Минимальный изолированный элемент = **1 тайл**
- Требует атлас из 47 спрайтов/тайлов
- Индексация: побитовая по часовой стрелке (N=1, NE=2, E=4, SE=8, S=16, SW=32, W=64, NW=128)

### Vertex-Centric (наш подход)

- Данные хранятся на сетке `(W+1) x (H+1)` вершин — только углы тайлов
- Каждый тайл определяется конфигурацией **4 вершин** (2x2 ячейки вокруг угла)
- Используется классификация Marching Squares: **15 типов** + Unknown (16 значений из 4 бит)
- Высоты на вершинах непрерывные (не бинарные), что даёт континуум форм через аналитическую геометрию
- Минимальный изолированный элемент = **2x2 тайла** (одна вершина влияет на 4 тайла)
- См. `src/apps/Landscape3dPlayground/LandscapeTileRules.h` — `LandscapeTileType`, 15 вариантов
- См. `src/apps/MeshGenerationPlayground/main.cpp` — `classifyVertex()`, 5 типов вершин

## Ключевое различие

| | Blob 47 | Vertex-Centric (наш) |
|---|---|---|
| Точек данных | edge midpoints + corners | только corners (вершины) |
| Бит на тайл | 8 | 4 |
| Типов тайлов | 47 уникальных (с учётом поворотов) | 15 + Unknown |
| Минимальный элемент | 1 тайл | 2x2 тайла |
| Геометрия | выбирается из атласа | генерируется процедурно из высот вершин |

## Решение: уменьшение ячейки

Вместо расширения модели данных до edge midpoints (и роста числа тайлов до 47) — **уменьшить размер ячейки в 2 раза** по X и Y:

- При ячейке в 2 раза меньше сетка `(2W+1) x (2H+1)` получается естественным образом — вершины мелкой сетки становятся теми же edge midpoints
- 4 мелких тайла = 1 blob-тайл по покрытию, та же разрешающая способность
- Остаёмся на **15 типах** — проще логика, проще атласы
- Данных в 4 раза больше, но это просто высоты на вершинах — без усложнения модели
- Mesh generation в 4 раза больше вершин, но для десятков тысяч ячеек это незначительно

## Вывод

Vertex-centric подход с уменьшенной ячейкой даёт ту же разрешающую способность что blob 47, но с меньшим числом типов тайлов и процедурной генерацией геометрии вместо атласов.
