# FencePathPlayground — забор и дорожки

_Вынесено из `AGENTS.md` (2026-09-06): корневой файл — компактная входная точка, подробности подсистем живут в `docs/`. Правя соответствующий код, обновляй **этот** документ._

`src/landscape_playgrounds/FencePathPlayground` — стенд для экспериментов с расстановкой забора и дорожек: сетка и камера портированы из SDFGeneratedLandscape — `GridRenderer` (оверлей-пасс AtlasRenderer без атласов и полевых слоёв: diamond-контуры клеток, одноклеточный hover-курсор с заливкой (куски забора занимают ровно одну клетку — нод-футпринт и node-marker убраны), те же `bakedDepth`/`kZFar`/`kZScale`, color-шейдер в трёх диалектах, один dynamic-буфер на tri+line дравы, явный alpha-over в бленде) + `Camera2D`/`DiamondIsometry` из topology_core (RMB-пан, wheel-зум к курсору 0.15..3, вся сцена в точках, пиксели только в viewport/glReadPixels). Карта 24×24 клетки. CLI `--shot/--zoom=/--center=/--no-ui/--smoke/--demo-fence` (smoke — CPU-проверки раунд-трипов проекции + сценарии FenceModel, TEST PASS/FAIL). На macOS дефолт Metal; для `--shot` — opt-in `-DFPP_FORCE_GLCORE=ON` (шаблон SDFGL, после проверки вернуть Metal-дефолт; ещё грабля: `--shot` пишется через `=`).

**Инструмент забора (FencePathPlayground).** Модель — чистый C++ `fence_core::FenceModel` (без sokol/Qt, стиль LandBrush; **градуировал в `src/libs/fence_core`** при переносе забора в редактор — плейграунд живёт на либе, локальных FenceModel/FenceMesh больше нет): клетка пуста или занята куском (piece) — **столб** (1 клетка) или **секция** (1–2 клетки по оси, соединяет ровно два столба). Забор = компонента связности **графа кусков** (столбы — вершины, секции — рёбра, связи хранятся явно через persistent id кусков: параллельные заборы в соседних рядах НЕ сливаются — связность по графу, не по соседству клеток); `fenceId` пересчитывается BFS после правки с сохранением старых id (компонента держит минимальный из id своих кусков — выделение переживает перенос/чужие правки), `version()` как у LandBrush. Два режима границ: `reset(w,h)` — bounded (плейграунд), `reset()` — unbounded (редакторские карты; `loadPieces()` перестраивает модель из плоского списка кусков детерминированно — id = порядок, звенья postA/postB геометрически). Раскладка штриха (`planStroke`): штрих всегда прямой и ось-параллельный; последовательность столб-секция-…-столб с предпочтением 2-клеточных секций (k секций, минимум k: новая линия N≥3 — `P S P`, достройка от столба N≥2 — `S P`; сумма длин секций = N − posts(k), 2-клеточные идут первыми). Штрих стопорится перед первой занятой клеткой: столб — хвостовая секция подключается к нему (слияние заборов), секция — просто конец линии без стыка. Повороты/T-вилки — отдельные штрихи от общего столба. `erasePostAt` сносит столб и инцидентные секции → забор распадается на независимые компоненты (висячих секций не бывает по построению); обратное слияние — обычной достройкой. Перенос — `canTranslate`/`translateFence` (конфликт с чужими кусками и выход за карту отклоняются, своё перекрытие разрешено), удаление — `eraseFence`. **Грабля при отладке:** ведущий столб новой линии занимает стартовую клетку — курсор раскладки обязан шагнуть с неё ПЕРЕД первой секцией, иначе секция затирает столб в cell-map (симптом: «достройка от столба не видит столб»). Ввод (main.cpp): LMB-drag с пустой клетки — новая линия, со столба — достройка (ось — по доминантной дельте драга, ghost-превью зелёный/красный); дабл-клик по столбу — выделить весь забор (sokol дабл-клик не отдаёт — детект по времени ≤350 мс + той же клетке); drag по выделенному — перенос; `Delete`/`Backspace` — удалить выделенный забор или столб под курсором; `Esc`/клик по пустоте — снять выделение; erase-режим — чекбокс в панели. Рендер — `FenceRenderer` (тот же color-проход, свой буфер): секции — утолщённые полосы между центрами столбов, столбы — залитые ромбы; выделение янтарём; ghost — полупрозрачный. Smoke — `FenceToolSmokeTest.cpp` (точные сигнатуры раскладки N=3..8/2..5, merge/block/T-вилка, split/rejoin, translate/erase) + gtest-двойник `src/tests/fence/fence_model_test.cpp`.

**3D-куски забора (FencePathPlayground).** Committed-куски рендерятся печёными мешами из `fence.shp` (ShapeML): пакетный экспорт `--export/--export-name/--param` ShapemlPlayground'а печёт 4 куска в `resources/models/fence/` (`fence_post`, `fence_corner`, `fence_section2` — шаг постов 2 м, `fence_section3` — 3 м; metal=1 вердигрис, сиды зафиксированы) — GPL-либа `shapeml_ref` по-прежнему линкуется только в ShapemlPlayground, плейграунд грузит печёные OBJ+MTL. `fence_core::FenceMesh` (градуирован в либу вместе с моделью) — чистый C++: минимальный OBJ/MTL-парсер под формат их `Exporter`'а (`usemtl`→`Kd`, грани `v/t/n`/`v//n`, дедуп по (v,n,mat)), `isCornerPost` (уголок = ровно 2 перпендикулярные секции) и CPU-инстансинг `buildFenceWorldTriangles` в мир (полевая проекция остаётся у потребителя — в плейграунде это shim `FenceFieldProject.h`, в render_core — `FenceRenderer`): мир 1 клетка = 1 м, пост на центре клетки (**центр клетки — ЦЕЛАЯ точка мира (cx,cz)**: `mapToField` отдаёт центр ромба для целых координат, клетка спанит `[cx−0.5, cx+0.5)`; офсет +0.5 сажает пост на Down-угол ромба = узел сетки — была такая бага), yaw-крутка по id (разнообразие сколов), секция — yaw по направлению postA→postB; свет (hemisphere + lambert) печётся в цвет вершины, выделение — янтарный тинт. `FenceMeshRenderer` — тот же color-шейдер, что у GridRenderer (вершина `FenceFieldVertex` бит-в-бит `GridColorVertex`), но **единственный проход с depth write ON** (самоокклюзия булыжников); z — общая конвенция + высотный член `y·96·0.5` (окно 0<F<1: поднятое выигрывает свой ряд, проигрывает ближним). Инстанс-буфер кэшируется по `(FenceModel::version(), selectedFence)` — камера/зум в VS, ребилд только на правках. Порядок кадра: сетка (без записи) → меши (запись) → `FenceRenderer` (в 3D-режиме только ghost, `drawSchematic=false`). Debug-фолбэк: `--flat-fence` / чекбокс «3D fence pieces» (авто-фолбэк при отсутствии файлов). Smoke — mesh-блок в `FenceToolSmokeTest.cpp` (загрузка/AABB, уголок на L-заборе, учёт вершин, подъём апекса, тинт выделения).
