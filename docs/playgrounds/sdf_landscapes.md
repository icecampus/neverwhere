# SDF-плейграунды: SDFGeneratedLandscape, SDFWithMaterialLandscape, HighgroundWithEffects

_Вынесено из `AGENTS.md` (2026-09-06): корневой файл — компактная входная точка, подробности подсистем живут в `docs/`. Правя соответствующий код, обновляй **этот** документ._

## Стенды и учебные слои

`src/landscape_playgrounds/SDFGeneratedLandscape` раздвоён: **SDFGeneratedLandscape** — чистый стенд отладки генерации геометрии (состояние до эффектов стыковки), **HighgroundWithEffects** — форк с эффектами стыка (общее солнце, контактное AO, shadow map, материалы стыка, grass underlay; также HiDPI-фикс сцены в точках). Геометрические кисти («Cliff 3D», «Stone 3D») и конвейеры одинаковы в обоих; эффекты — только в Effect-версии.

У SDFGeneratedLandscape есть плоский слой «Texture 2D»: ландшафт из любой тайлящейся текстуры (`resources/textures`, подхват всех png/jpg на старте; все файлы пакуются в один texture array — `AtlasRenderer::buildTilingTextureArray`, билинейный ресемпл к общему размеру, слой массива = индекс файла). Текстура **не нарезается** на per-tile кусочки атласа (кусочки не сойдутся на стыках) — цвет сэмплится непрерывно в мировых (field) координатах (`v_world * tiling`, REPEAT-сэмплер, как `top_tex` у клифов), а Yellow-маска Flat-атласа работает только stencil (alpha), без рельефа кромок — поверхность читается как одно целое (у самого Yellow 2D тёмные окантовки ромбов — осознанный технический арт). В палитре каждая текстура — отдельный инструмент, сгруппированный под «Texture 2D», чтобы было видно, что слой один: нода хранит тег текстуры (`LandBrush::setNode(node, on, tag)`, tag = слой массива + 1, 0 = untagged), перекраска ноды другой текстурой вытесняет старую. Переходы между соседними текстурами — плавные: клетка тесселлируется веером из центра в 4 угловые ноды (ромб, `appendTileFan`), углы несут one-hot веса кандидатных текстур клетки (`LandBrush::cellTextureBlend`, ≤4 кандидатов; соседние клетки непрерывны, т.к. делят ноды на общем ребре), а FS миксует слои массива по интерполированным весам с органичным fbm-вобблом (гейт `w*(1-w)` — чистые интерьеры не трогает) и sharpness-экспонентой. Тем же веером растворяется и внешний контур региона: per-vertex fill (1 у on-ноды, 0 у off) интерполируется, альфа = smoothstep вокруг iso 0.5 (та линия, где раньше резала маска) с тем же fbm-вобблом — жёстких ступенек на границе с пустотой нет; ширина пера — слайдер edge fade (`blend_params.w`, 0 = жёсткий срез). Плоские не-текстурные слои (Grass/Yellow/силуэты клифов) идут квадом с fill=1 и не меняются. Все blend-параметры — живые юниформы (`blend_params`, слайдеры у слоя). Мажоритарное `cellTagAt` осталось для логики/фолбэка, рендер идёт через бленд; untagged-клетки (нулевые веса) падают в маску-only фолбэк. Реализация — world-UV режим плоского прохода `AtlasRenderer` (юниформы `tex_params`/`blend_params`; у мультитекстурного слоя `PaintLayerView::multiTexture` — один range на слой); CLI `--tex-nodes=` / `--tex-tiling=`. `--shot` там портируемый (glReadPixels, как у Effect-версии); захват ждёт устаканивания кэшей (ни один field-слой не `pending` после дебаунса) + 1 с wall-time, с фолбэком на 120 кадров — слепой счётчик кадров на llvmpipe под xvfb растягивал ожидание на минуты, а на быстрой машине кадры пролетали быстрее дебаунса 0.3 с и 3D-меши не успевали в кадр.

У SDFGeneratedLandscape есть учебный слой **«Box 3D»** — минимальный семпл поля по общему контракту: `boxfield::BoxField` (`BoxField.h/.cpp` в плейграунде, как TechOutlineField-форк) строит по одному axis-aligned боксу на закрашенную клетку (клетка занята, если горит любая из 4 угловых нод — правило `cellNonEmpty` из tech_field); `eval` — `min` по боксам (CSG-объединение), соседи сливаются только при `fill = 1` (общая грань), при `fill < 1` между клетками честные щели; `blurPasses = 0` — чёткие грани. Никакой интерполяции и shading-каналов (groove/rim пусты) — годится как отправная точка для экспериментов с формой: правится только `eval`. Свои params/height scale/CLI (`--box-nodes=`, `--box-fill=`), тот же кэш/debounce, что у остальных field-слоёв; smoke-сценарий — в `PlaygroundSmokeTest.cpp` (watertight при fill 1/0.6, пинч диагональных клеток для regularizeSigns, верх на boxHeight).

Следующий учебный слой — **«Circle 3D»**: `circlefield::CircleField` (`CircleField.h/.cpp` там же) рисует по вертикальному цилиндру (`max(radial, axial)` — точное CSG-пересечение бесконечного цилиндра со slab'ом `0..height`) вокруг каждой закрашенной **ноды** («круг вокруг вершины»), а клетка, у которой горят **все 4** угловые ноды (противоположный конец any-corner правила BoxField), становится полностью поднятым параллелепипедом `[cx,cx+1]×[0,height]×[cz,cz+1]` — тем же box-SDF с fill=1, поэтому соседние полные клетки сливаются бесшовно. `eval` — общий `min` по цилиндрам и боксам в радиусе `max(1, ceil(nodeRadius))`; дефолтный `nodeRadius = 0.55` чуть перекрывает соседние круги (сливаются в один блоб), а центр полной клетки (~0.707 от углов) добивает именно бокс — в smoke это различение проверяется отдельными `eval`-пробами. Padding авто-поднимается до `nodeRadius − 1 + 2·cellSize`, чтобы слайдер радиуса не вытолкнул F≤0 на границу поля. Свои params/height scale/CLI (`--circle-nodes=`, `--circle-radius=`), тот же кэш/debounce; smoke — watertight, верх/низ, покрытие центра полной клетки, внутри/снаружи одиночного цилиндра.

Третий учебный слой — **«Mask 3D»**: `maskfield::MaskField` (`MaskField.h/.cpp` там же) поднимает 2D-силуэт слоя «Texture 2D» в плиту с покатыми краями: footprint — билинейная интерполяция per-node fill по 4 углам клетки, маска `fill ≥ 0.5` (та же iso-линия, что рисует текстурный слой: стены проходят середины рёбер on→off, полузакрашенные клетки — клинья, одиночная нода — маленький блоб), а поле — `max(y − top(s), −(y + hh), s − S)`, где `hh = height/2` и `s = sd(x,z)` — растрированный signed distance к изо-линии `fill = 0.5`, отрицательный внутри (8 текселей на клетку, дробный посев по линейному пересечению нуля на рёбрах текселей + двухпроходный chamfer (1,√2) — тот же приём, что у контактного AO в `scene_stitch`; в `eval` сэмплится билинейно, поэтому `eval` по-прежнему O(1) и цикл по окрестности не нужен), а `top(s)` — высота верха: `+hh` по ядру (силуэт spread=0 держит полную высоту) и линейный спуск до `−hh` поперёк spread-полосы шириной `S = spreadDistance`. Геометрия стоит половиной высоты ниже плоскости нод-сетки (y=0): плита занимает `±hh`, подошва юбки достаёт до `−hh` — та же «подводная» посадка, что у берегового tech-конвейера. Шейдерные fbm-воббл и alpha-фейд в геометрию не переносятся — контур становится чёткой стеной. Параметр `spreadDistance ≥ 0` (слайдер Spread, в клетках) — ширина «юбки» вокруг плиты: полновысотной геометрии за пределами ядра нет, край плиты скатывается градиентом высоты под сетку, а подошва юбки скругляется дугами на выпуклых углах (свойство честного distance field); при 0 формула точно сводится к плите `max(s, |y| − hh)` — вертикальная стена на той же изо-линии, что рисует текстурный слой. Нулевое кольцо бордера обязано быть шире spread — margin в `rebuildCliffCache` выводится как `1 + ceil(spreadDistance)`, иначе подошва юбки обрежется краем поля. Свои params/height scale/CLI (`--mask-nodes=`, `--mask-spread=`), тот же кэш/debounce; smoke — watertight (в т.ч. юбки), верх/низ на ±hh, интерьер без трещин на общих рёбрах, стена на середине on→off ребра, spread — полная высота ядра, градиент склона в двух точках, пересечение плоскости сетки посередине полосы, подошва на линии off-нод и скругление угла.

`src/landscape_playgrounds/SDFWithMaterialLandscape` — форк SDFGeneratedLandscape, схлопнутый до одной кисти «Mask 3D» (вычищены texture-array/blend machinery, остальные полевые слои и multiTexture; у `PaintLayerView` только `brush/atlas/cliffHeightScale/mask/maskParams/shadingOverride`, у плоских тайлов quad-вершина без весов, плоский FS — чистый atlas-маска, `--mask-nodes/--mask-spread/--mask-sink/--shot/--zoom/--center` сохранены). Маска форка параметризована погружением: `sinkFraction` (дефолт 0.5 = поведение базового плейграунда) — доля высоты плиты под плоскостью нод-сетки (будущая вода): плита занимает `−height·sink..+height·(1−sink)`, подошва юбки достаёт `−height·sink` (0 — дно на сетке, 1 — полностью под водой; слайдер «Sink below grid», дебаунс как у остальных mask-параметров). Назначение — инкубатор PBR-lite материала для field-слоёв на комплекте ambientCG Ground061 (CC0, карты лежат в `resources/textures/ambientcg/Ground061/`, см. README там же): в клиф-шейдер (все три диалекта, как всегда) добавлен материал — трипланар-альбедо (карты 2:1, V тайлится вдвое чаще — хелпер `matuv`), top-проекционные нормал-мапа (Tangent-фрейм вокруг геометрической нормали, NormalGL), AO (душит ambient-член) и roughness (душит spec), силы — юниформы `CliffFsParams::params2` (tiling/albedo/normal/AO) и `params3.x` (roughness): при нулевых силах шейдер бит-в-бит палитровый, каждый `paramsN` реально читается в GLSL (атомарность юниформ). Текстуры — 4 view-слота + общий REPEAT-сэмплер (LINEAR_MIPMAP_LINEAR + aniso×8: карты грузятся с полной CPU mip-цепочкой, `uploadSlotMipmapped` + 2×2 box в `buildMipChain` — без мипов минимизированная REPEAT-текстура на плоскости земли алиасится в шум; атласы мипами НЕ снабжать — тайлы перетекут друг в друга), placeholder'ы 1×1 (белый цвет, плоская нормаль (128,128,255), белые AO/rough), загрузчик `AtlasRenderer::loadMaterialMaps(dir, setName)`. Микрорельеф (displacement) — честная геометрия, а не parallax: CPU-растр `maskfield::ReliefMap` (loader `loadReliefMap`, grayscale 0..1) сдвигает изо-поверхность в `MaskField::eval` на `reliefDepth·(sample−0.5)·2` (REPEAT-билиней, тот же аспект 2:1). Растр при загрузке low-pass'ится повторным 2×2 box-халвингом с REPEAT-обёрткой до ~32×16: воксельная сетка физически не держит мелкую рябь исходной карты (строки ~0.03 мира = под воксель) — она превращалась в гравийный лумп-шум; геометрии остаются только дюны крупного масштаба, мелкая рябь живёт в нормал-мапе. Рельеф затухает к контуру ядра (`reliefFade` ~0.15 мира, smoothstep по −s) — стены и юбка держат чистый силуэт, дюны только на верхе плиты. Разрешение воксельное (дефолт cellSize 0.04 вместо 0.06), дефолты tiling 1.0 / depth 0.02 (CLI `--mat-tiling=` двигает и reliefTiling — дюны совпадают с рябью шейдера); при `reliefDepth=0` поле бит-в-бит гладкое; при `reliefDepth=0` поле бит-в-бит гладкое. Смена растра видна params-mempcmp'ом через счётчик `reliefVersion` (указатель в params + бамп при релоаде). UI — секция «Material (Ground061)» (силы мгновенны, relief-параметры дебаунсятся), CLI `--mat-dir=`/`--mat-tiling=`/`--relief-depth=`/`--mask-sink=`; материал выключается по умолчанию при промахе загрузки (силы зануляются в init). Smoke — рельефный блок: амплитуда ±depth на uniform-картах, билинейная проба на градиентной, watertight с рельефом; sink — пробы верха/низа по доле погружения. **Поле градуировало в библиотеку:** каноничный `mask::MaskField` теперь в `highground_core/mask_field.h` (+ `mask::reliefMapFromImage` — low-pass растра переехал туда же), в плейграунде остался лишь shim `MaskField.h` (`namespace maskfield = mask;`), а в редакторе поле живёт как mask3d-ассет (см. буллет выше).

## Z-буфер плоского iso (грабли)

**Z-буфер SDFGeneratedLandscape (грабли).** Глубина в плоском iso печётся из **ground-y** точки (`bakedDepth(fieldY)` в `AtlasRenderer.cpp`): field-y растёт к зрителю, поэтому при LESS_EQUAL + clear 1.0 ближнее — меньшее z. Анкер обязан быть **константой, а не от камеры**: cliff/stone/tech-стримы пекут z один раз при (дебаунсенном) ребилде меша, а оверлей пересчитывается каждый кадр — камеро-зависимый анкер расходится между ними, и панорамирования на одну клетку хватало, чтобы сетка перескочила из-под меша наверх (у HighgroundWithEffects та же константа `kZFar`/`kZScale`). Оверлей (сетка, hover-футпринт) сидит **на самой плоскости земли** — тот же `bakedDepth` от своего field-y, и это осознанно «поверхность воды»: высота фрагмента сдвигает его только **вверх** по экрану, т.е. на ряды **дальше** своего, поэтому поднятая геометрия всегда выигрывает у сетки, которую накрывает, а то, что висит **ниже** плоскости (стенки цокольной плиты, подводная нога Tech 3D Outline), уезжает вниз в ближние ряды и проигрывает их линиям сетки — читается как «под водой». Высотного члена в глубине для этого не нужно, знак и так верный. То же самое в редакторе: `render_core::OverlayRenderer` даёт grid-каналу отдельный пайплайн с LESS_EQUAL + depth write (`WorldRenderer` считает per-corner z по той же конвенции `z_range`, что 3D-пассы), cursor-канал остаётся ALWAYS без записи. Спрайты (Tile2D) сидят в общем z-контракте: каждая вершина квада несёт CPU-запечённый clip-z по формуле `liftedGroundY(anchorY, liftPx)` от базовой линии (нижняя кромка изображения) — спрайт эквивалентен вертикальной стене на своей клетке; пайплайн `LESS_EQUAL` **без записи** глубины (спрайты — последний мировой проход: тест арбитрирует в обе стороны против 3D, между собой — painter-порядок по `zOffset` без z-fight'а, воде под ними остаётся её глубина), а `kSpriteZBias` (`depth_levels.h`, > `kGridZBias`) держит ноги спрайта поверх ко-планарной сетки и глушит ULP-шум о плоскость земли.

## HighgroundWithEffects: стыковка хайграунда с землёй

Хайграунд «висел в воздухе»: земля рисовалась сырой текстурой рядом с освещённым мешем, без единого света, теней и AO. Сейчас оба пасса живут в одной световой модели (`AtlasRenderer` + `SceneStitch.h/.cpp`):

- **Кадр — два этапа.** `AtlasRenderer::prepare(SceneFrame)` (перестройка меш-кэшей, AO-поле, shadow-пасс) вызывается **до** открытия swapchain-пасса, `render(SceneFrame)` — внутри него. Offscreen-пасс внутри swapchain-пасса открыть нельзя, поэтому разделение обязательное.
- **Общий блок юниформ** `SceneStitchParams` (солнце, ортобазис тени, тон, силы AO/тени) идёт в оба FS. Ground-пасс берёт его целиком, cliff-пасс — только «ядро» (`kStitchCoreBytes`, без `ao_rect`): GL-драйвер выкидывает неиспользуемые юниформы, и sokol на каждом старте ругался `GL_UNIFORMBLOCK_NAME_NOT_FOUND_IN_SHADER`. По той же причине у cliff-пасса нет своего `light_dir` — солнце одно на сцену.
- **Земля пишет глубину** (`kGroundDepth`, одна константа за всей сценой) и несёт мировые координаты в `TexVertex` — `worldFromField()` инвертирует `DiamondIsometry::nodeToField`, так что фрагмент земли знает свою клетку и может сэмплить AO-поле и shadow map в кадре меша.
- **Контактное AO** — CPU chamfer distance transform от контура хайграунда (`buildContactAoField`, кэш по `LandBrush::version()`), выгружается в R8; в шейдере расстояние нормировано `kAoMaxDistanceCells`, ширина полосы — `aoRadius` (в клетках), сила — `aoStrength`. Та же сила поднимается по самой стене (`aoWallFade` — высота затухания в единицах меша, едет в cliff-шейдер через `CliffFsParams::params7.w`): если затемнять только землю, камень прямо над ней остаётся светлым и шов, который AO прячет, наоборот подчёркивается. Ключевое: маска берётся **субклеточная**, по тому же правилу частичного заполнения, что рисуют превью-тайлы (`diamondNodeFill` в `LandBrush.h`, общая с `FlatAtlasGenerator`) — клетка это ромб с нодой в каждом углу, и наполовину зажжённая клетка залита клином, а не целиком. С побитовой «клетка занята / не занята» затемнение отступает от диагональной стены на целую клетку и обводит границы клеток, а не сам клиф. Отсюда 8 текселей на клетку (клин у половинной клетки идёт через центр) и дробный посев chamfer'а по линейному пересечению нуля: округление контура до целых текселей даёт лесенку на косых стенах.
- **Shadow map выключен по умолчанию** (`SceneStitchSettings::shadowsEnabled = false`, пасс при этом даже не рендерится): жёсткая солнечная тень поперёк тайлов спорит с освещением, уже запечённым в атласной графике, а стыковку тянет контактное AO. Сама реализация оставлена под галкой — ортопроекция солнца (`buildSunBasis`) в **R32F color attachment** (+ depth attachment для видимости): depth-only пассов и сэмплирования depth-текстур в репо нет вообще. Сэмплер обязан быть `NONFILTERING` / `UNFILTERABLE_FLOAT` (float-таргет не гарантированно фильтруемый), PCF 3×3 руками. Высота меша приводится к клеточным единицам через `isoHeightToWorld(halfW, halfH, heightScale)`, иначе тень не совпадёт по длине с силуэтом.
- **Материалы стыка** (юниформы, без ребилда меша): рефлекс травы снизу и тон неба сверху, затемнение кромки по per-vertex `rim`, у верха плато свои тинт/яркость/тайлинг/поворот UV — он делит `grass.png` с землёй и без этого читается как её продолжение.
- **Два эффекта выключены по умолчанию, но код оставлен:** травяная юбка на подошве стены (`SeamParams::overgrowth = 0`) даёт плоские зелёные кляксы по камню, читающиеся как ошибка текстуры, а кольцо валунов (`ScreeParams::enabled = false`, `appendScreeRing` — дописывает валуны в тот же cliff-поток вершин с `groove = -1` как маркером «палитра стены») рассыпает одинаковую процедурную гальку. И то и другое подножие хочет получить геометрией: отдельной кистью пропов с набором, который подбирает художник под окружение. В шейдере у юбки есть явный гейт `step(1e-4, params4.x)` — без него `step()` против нулевого порога всё равно срабатывает там, где шум ровно ноль.
- **Направление солнца** правит ламбертом обоих пассов и (если тень включить) её длиной: азимут 3π/4 кладёт тень горизонтально по экрану — иначе она прячется за силуэтом меша, который поднят вверх, — а низкая высота даёт ей длину, на которой её видно.
- Проверка: `--smoke` (в т.ч. CPU-проверки AO-поля и ортонормированности базиса), `--shot` теперь портируемый (glReadPixels в TU с `SOKOL_IMPL`; glad подключать нельзя). На Linux скриншоты — под `xvfb-run`. На macOS у Metal `--shot` нечем читать (readback только в GLCORE-ветке), а системный `screencapture` из терминала без Screen Recording-пермишена отдаёт чёрный кадр — для скриншотов standalone-плейграундов на macOS переконфигурировать с GLCORE-бэкендом (у SDFGeneratedLandscape есть opt-in `-DSDFGL_FORCE_GLCORE=ON`, sokol_app на macOS умеет GL); после проверки вернуть Metal-дефолт.

## HiDPI в sokol_app + ImGui (грабли)

**HiDPI в sokol_app + ImGui (грабли, стоившие «кисть красит не там, где курсор»).** `sapp_width()/sapp_height()` и `ev->mouse_x/y` — **пиксели фреймбуфера**, а ImGui (и, значит, ширина панели) живёт в **логических точках**: `simgui_new_frame()` сам делит размер на `dpi_scale`, а `simgui_handle_event()` — координаты мыши. Стоит вычесть ширину панели (точки) из позиции мыши (пиксели), и на `dpi_scale = 2` курсор уезжает на пол-панели, а viewport, посчитанный как «(пиксели − точки) × dpi», раздувается вдвое. В HighgroundWithEffects вся сцена (камера, мышь, `SceneFrame::viewW/viewH`) теперь в точках — `dpiScale()`/`windowSize()` в `main.cpp`, — а в пиксели переходит ровно одно место, `sg_apply_viewport`, плюс `glReadPixels` на скриншоте. Проверять это под Xvfb можно: `dpi_scale` sokol берёт из `Xft.dpi` в свойстве `RESOURCE_MANAGER` корневого окна, а голый Xvfb **сбрасывается при отключении последнего клиента** и свойство теряет — ставить его и запускать приложение надо с одного живого X-соединения (питоновский `Xlib` + `xtest` для синтетических кликов).
