## Репозиторий и архитектура

- Это **один monorepo**: приложения и библиотеки живут под существующей структурой (`src/apps/`, `src/libs/`).
- Не плодить изолированные проекты со своими `project(...)` без необходимости.
- **Основной стек:** C++20 для логики, Qt 6 / QML для UI редактора, Dear ImGui для UI рантайма.
- Не вводить тяжёлые зависимости без согласования.
- `src/libs/core` — бизнес-логика ядра; `src/apps/EpicMapEditor` — UI/приложение редактора.
- `src/libs/highground_core` — генерация геометрии поднятой 3D-земли (стены + верх) по vertex-нодам; чистый конвейер `Grid + Params -> generate() -> Mesh`, без Qt/GPU. Там же (см. `cliff_field.h`/`surface_nets.h`) живёт cliff-field конвейер: сетка нод -> scalar field (плато + omphalos-борозды) -> surface nets -> watertight-mesh (используется кистью «Cliff 3D» в SDFGeneratedLandscape; standalone CliffFieldPlayground удалён за ненужностью — его сценарий живёт в `src/tests/highground/cliff_field_test.cpp`). Поднятая земля (`generate()`) общая для редактора/клиента (через `render_core`); cliff-field конвейер отлаживается в SDFGeneratedLandscape (кисть «Cliff 3D») — удобнее, чем в редакторе. Там же (`tech_field.h`) живёт tech-field конвейер — перенос семантики технических атласов TechnicalGrass Ridge/Valley (`utils/asset_generator/technical/`) в геометрию: fan-heightfield по нодам (4 угла + центр клетки), оба тайлсета сведены к одному генератору с блендом `style` через высоту центра (split Valley для Lack тождественен fan с центром=1); «стены» Python-атласов были артефактом экранной проекции, в 3D поверхность непрерывна по общим нодам; тёмный контур тайлов — shading-only groove-канал (creaseWidth). Таблица высот центра обобщена с бинарной на пары (maxV,minV) — для {0,1} бит-в-бит. Береговая линия (`outlineDepth > 0`): по принципу «yellow around green» 8-связная дилатация ленд-нод минус сам ленд становится outline-кольцом со значением `-outlineDepth` (ноды трёхзначные: land +1 / outline −k / пусто 0 = открытая вода), склоны граничных тайлов продолжаются под воду (y<0) — «подводная часть»; наружу подошва **не** возвращается к нулю: клетка с outline-углами, но без ленд-угла, держит `-outlineDepth` по всей своей площади (подводная полка), а дальше идёт открытая вода без outline-углов, которую снимает `side` — формация кончается обрывом ниже линии воды; `eval` — max(top, bottom(min(h,0)−baseDepth−y), side, footprint): `side` клипует открытую воду (h≈0 и ∇h=0), но пощадит нулевые пересечения рамп (по |∇h| сектора — трещины на линии воды нет), `footprint` держит поле положительным на границе сетки; bbox в rebuild при outline — маржа 2 (кольцо растёт на клетку). **Грабли:** твёрдь обязана быть ≥ ~2 вокселей (`baseDepth = max(groundDepth, (2.2+blurPasses)·cellSize)`) — при толщине < вокселя верх и низ слипаются в общие вершины (мембрана с битыми нормалями и полосами в шейдинге), а blur-проходы такую мембрану стирают совсем; `blurPasses=1` по умолчанию — сглаживает террасацию naive surface nets на склонах. Используется кистью «Tech 3D» в SDFGeneratedLandscape (тот же кэш/debounce, что у «Cliff 3D»/«Stone 3D», своя земляная палитра через shading override), тесты — `src/tests/highground/tech_field_test.cpp`. Кисть «Tech 3D Outline» там же полностью отделена от «Tech 3D»: рендерит береговой вариант через плейграундный форк `tech_outline::TechOutlineField` (`TechOutlineField.h/.cpp` в SDFGeneratedLandscape, стартовое состояние — бит-в-бит копия библиотечного поля с `outlineDepth=1`), со своими params, height scale и палитрой — методы генерации берега можно менять, не трогая библиотеку.
- `src/libs/landscape_mesh` — клеточная маска (`SolidMaskGrid`, см. `solidMaskFromNodes` для vertex-нод -> маска) -> `composeSolidMaskMesh()` -> plateau-полоса (верх + стены по границе, квады `MeshQuad` с запечённым цветом), один уровень = один вызов. Стили стен подключаемые: `IWallStyle` + `WallStyleId {BlockCliff, Cyclopean}` + `makeWallStyle()` (`wall_style.h`); `CyclopeanStyle` — порт Blender-прототипа `prototypes/blender/clifs/cyclopean_walls/clifs.blend`. Используется в PolygonalGeneratedLandscape; в `render_core`/редактор заведён как отдельный тип ассета `cyclopean3d` (`CyclopeanAsset`, слой `CyclopeanLandscape`, `render_core::CyclopeanRenderer` с хардкодом `WallStyleId::Cyclopean`, панель `CyclopeanSettings.qml`) — по шаблону интеграции cliff3d.
- stone3d-ассеты (`StoneAsset`, слой `StoneLandscape`, панель `StoneSettings.qml`) рендерятся тем же `render_core::CliffRenderer` (общие пайплайн/кэш/debounce): меш — через `stone_gen::StoneField` (блок `CliffParams::stoneField`, вершина с rim-атрибутом), шейдинг — stone-экстрами в `CliffFsParams::params4` (plane-Y гейт верхней палитры, rim-градиент к кромке, микс текстуры верха); чистый клиф при нулевых stone-каналах шейдится бит-в-бит как раньше. Сборка кадра — `WorldFrame::stoneTiles` + `WorldRenderer::ensureStoneAsset` (редактор `ModelFrameSource`, клиент/Play `world_frame_builder`; конвертеры `stoneParamsFromAssetData` рядом с `cliffParamsFromAssetData`). Cliff- и stone-тайлы идут в cliff-пасс **одним объединённым вызовом** `CliffRenderer::render` за кадр: у прохода per-frame scratch-буферы (превью-силуэты), а sokol разрешает лишь один `sg_update_buffer` на буфер за кадр — два вызова подряд под правками в обоих слоях давали `VALIDATE_UPDATEBUF_ONCE`.
- tech3d-ассеты (`TechAsset`, слой `TechLandscape`, панель `TechSettings.qml`) рендерятся тем же `render_core::CliffRenderer` по шаблону stone3d: меш — через `tech::TechField` (блок `CliffParams::techField`, конвертеры `techParamsFromAssetData` в обоих доменах, ветки в `rebuildRegion`/`regionKey`/`plateauHeightOf`), а шейдинг — палитрой per-asset через `CliffShading` (дефолты `Tech3dAssetData`: earth ramps, `veinThreshold=2` (veins off), `bottomDarken=0`), тёмный контур тайлов рисует существующий groove-канал (crease из поля), stone-экстры `params4` остаются нулевыми, rim=0; добавленный FS-канал — `params3.z` (`underwaterFade`, растворение под водой, см. модель уровней ниже). Сборка кадра — `WorldFrame::techTiles` + `WorldRenderer::ensureTechAsset`; tech-тайлы входят в тот же объединённый вызов cliff-пасса (cliff+stone+tech одним `render`) и в stitch-футпринт AO. Параметр `outlineDepth > 0` включает береговую линию (outline-кольцо с подводной частью, см. tech_field; bbox в `rebuildRegion` тогда с маржой 2); подводная часть растворяется в воде градиентом прозрачности через `underwaterFade` (0 = выкл; 0.35 = один level в бандле TechGrassOutline, слайдер в TechSettings). Бандлы-примеры: `resources/assets/landscape/TechGrass` (суше) и `TechGrassOutline` (берег, `outlineDepth=1`).
- mask3d-ассеты (`MaskAsset`, слой `MaskLandscape`, панель `MaskSettings.qml`) рендерятся тем же `render_core::CliffRenderer` по шаблону tech3d: меш — через `mask::MaskField` (блок `CliffParams::maskField`, конвертеры `maskParamsFromAssetData` в обоих доменах, ветки в `rebuildRegion` (margin = `1+ceil(spreadDistance)`)/`regionKey` (скаляры + `reliefVersion`)/`plateauHeightOf` (=`height·(1−sink)`)), нода-маска поднимается в плиту с покатой юбкой (spread), стоящую на `sinkFraction` высоты ниже уровня воды — песчаный берег. Шейдинг — PBR-lite материал из бандла (`materialSet`: `<set>_Color/_NormalGL/_AmbientOcclusion/_Roughness.jpg` + `_Displacement.jpg`): трипланар-альбедо (карты 2:1, V тайлится вдвое чаще — `matuv`), top-проекционная нормал-мапа (NormalGL), AO→ambient, roughness→spec; юниформы — `CliffFsParams::params9` (tiling/albedo/normal/AO) и `params10.x` (roughness); при нулевых силах (пустой `materialSet` — конвертеры их зануляют) шейдер бит-в-бит палитровый (песочные дефолты `Mask3dAssetData`). Текстуры — FS views 1..4 + общий mipmapped REPEAT-сэмплер слота 1 (мип-цепочка CPU — `render_core/image_loader.h` `buildMipChain`; +aniso×8; атласы мипами НЕ снабжать), per-asset ленивая загрузка в `CliffRenderer::render` (кэш `AssetCache::matImages/matViews`, placeholder'ы 1×1 белый/плоская нормаль при промахе), CPU-рельеф — `mask::ReliefMap` из `_Displacement.jpg` (low-pass до дюн в `mask::reliefMapFromImage`), renderer сам подтыкает растр в `maskField->reliefMap` перед ребилдом региона. Сборка кадра — `WorldFrame::maskTiles` + `WorldRenderer::ensureMaskAsset`; mask-тайлы входят в тот же объединённый вызов cliff-пасса (cliff+stone+tech+mask одним `render`) и в stitch-футпринт AO. Кисть — `MaskPencil`; тесты — `src/tests/highground/mask_field_test.cpp`, `src/tests/assets/mask3d_asset_data_test.cpp` + `mask_asset_test.cpp`. Бандл-пример: `resources/assets/landscape/SandBeach` (с картами Ground061 и thumbnail; демо-глава `resources/chapters/mask3d_test`). **Грабли:** у пляжа подводная часть мелкая и широкая (десятые доли уровня), а рамп water-surface прохода шелла (`surfaceFadeDepth` = 0.6 уровня) откалиброван под глубокий шельф tech-outline (−1 уровень → полная непрозрачность) — на пляже α воды не поднимается выше ~0.1–0.3, и без `underwaterFade` берег читается как суша, «не пересекающая» воду. Поэтому у SandBeach `shading.underwaterFade = 0.25` (≈ глубине подошвы юбки `height·sinkFraction`): подводная часть растворяется в воде FS-градиентом, линия уреза становится видимой (слайдер есть в MaskSettings). Мелочь: water-surface проход меряет глубину в уровнях через захардкоженный `kWaterHeightScale = 96` (дефолт клифов); у ассетов с другим `raisedHeight` (у SandBeach 128) измеренная глубина пропорционально ошибается — на крутизне рампа сказывается, на положении уреза нет.
- texture2d-ассеты (`TextureAsset`, слой `TextureLandscape`, payload `"texture2d"` в index.json: файл тайлящейся текстуры + `tilingRepeats`; v1 без QML-панели) — порт слоя «Texture 2D» из SDFGeneratedLandscape: плоская земля с world-UV тайлящимися текстурами, плавный бленд соседних текстур и растворение контура в пустоту. Рендер — `LandscapeRenderer::renderTexture` (вызывается из `WorldRenderer::render` **после** всех 3D-проходов, до сетки: покрытие блендится с тем, что реально под ним уже нарисовано — пляж/земля/вода, — а не выгрызает альфой дыру в геометрии, нарисованной позже; пайплайн `compare=LESS_EQUAL` без depth write, per-cell z плоскости 0 плюс кавер-лифт `kTextureCoverLiftPx` в `ground_params.y` арбитрирует исход — поверх низкого рельефа mask3d-пляжа, но под любое поднятое 3D, см. модель уровней ниже; stitch-шейдинг тот же): все текстуры живут в одном texture array (по срезу на ассет, `ensureTextureAsset`, ребилд лениво при смене набора), клетка тесселлируется веером (центр + 4 угловые ноды) с one-hot весами кандидатов и fill-весом, FS — порт плейграундного (микс по весам с fbm-вобблом и sharpness, alpha = smoothstep вокруг iso 0.5). Per-node тегов текстур в карте НЕТ (хранится per-cell tileIndex + assetUuid): текстура ноды восстанавливается голосованием — `render_core/texture_blend.h` `buildTextureBlendCells` (каждая клетка голосует своим assetUuid за включённые углы; ничья — в пользу кандидата с более поздним первым голосом ≈ last-paint-wins), покрыто `src/tests/render_core/texture_blend_test.cpp`. Бленд-параметры (sharpness/noise/edgeFade) — публичное поле `WorldRenderer::textureBlend` (дефолты плейграунда, юниформы, v1 без QML), тайлинг — per-asset из JSON (едет в вершине). Кисть — `TexturePencil` (наследник `LandscapePencil`, логика без изменений: assetUuid per cell пишется сам), данные — те же Landscape-тайлы. Бандлы-примеры: `resources/assets/landscape/TextureGrass`, `TextureRock`.
- Эффекты стыка хайграунда с землёй портированы из HighgroundWithEffects в `render_core` (общие для редактора/клиента): `render_core/scene_stitch.h` (CPU-половина: `buildContactAoField`, `SceneStitchSettings`/`SceneStitchParams`, `SeamParams`, `kStitchCoreBytes`) + `WorldRenderer::prepare(frame, nowSec)` (вызывается шеллом **до** `sg_begin_pass`: пересобирает объединённый нод-футпринт raised+cliff+stone+cyclopean в R8 AO-текстуру при смене контент-ключа; пустое поле → placeholder 1×1=255; владеет AO image/view/sampler и shared stitch-блоком). Настройки — публичные поля `WorldRenderer::stitch`/`seam` (дефолты плейграунда, v1 без QML). Земля (`LandscapeRenderer::render`, сигнатура с `GroundStitchContext`) несёт world-координаты в вершине, сидит на плоскости уровня 0 (per-vertex z из ground-y по общей z_range-конвенции `depth_levels.h`; depth write ON, LESS_EQUAL — тайлы земли разрешаются painter-порядком, 3D выигрывает высотным членом, подводная геометрия проигрывает плоскости) и шейдится общим солнцем/тоном + контактным AO (полный 64-байтный stitch-блок с `aoRect`); старый per-node `CliffShadowField` удалён. Cliff-пасс берёт солнце из stitch-ядра (48 байт, слот 2; per-asset `lightAzimuth/lightElevation` в `CliffShading` оставлены для JSON-совместимости, но не используются) и несёт seam-каналы в `CliffFsParams::params5..params8` + яркость верха в `params3.y` (rim contact AO, bounce/sky тинты, тинт/яркость/rotation верха, foot AO по `stitch1.z`; нулевые силы = поведение как до порта). Грабли: в GLSL stitch-пара после `sun_dir` объявлена массивом `uniform vec4 stitch[2]` — драйвер выкидывает неиспользуемые именованные юниформы (ground-only `stitch0` в cliff FS не потребляется), и sokol рапортует `GL_UNIFORMBLOCK_NAME_NOT_FOUND_IN_SHADER`; массив атомарен, пока жив хоть один элемент.
- **Модель уровней глубины (`render_core/depth_levels.h`):** уровень фрагмента = его мировая высота y (вода/сетка = 0, верх хайграунда = +1 level, береговая подводная часть = до −1). Все проходы пекут z по единой формуле `z = (zFar − (groundY + y·heightScale·kDepthHeightFactor))·kZScale` (LESS_EQUAL, clear 1.0, ближе = меньше z): высотный член добавлен в CPU-проекции cliff/cyclopean/raised (раньше был только ground-y; `liftedGroundY`), поэтому поднятое (y>0) строго ближе плоскости воды, подводное (y<0) строго дальше, а на общем экранном ряду iso-корректно выигрывает более высокий фрагмент; будущий стекинг «хайграунд над хайграундом» изменений рендера не потребует (y непрерывен). Плоская земля и texture2d слезли с константной глубины 0.999 на per-cell z (плоскость 0; у texture2d — плюс кавер-лифт) (VS-блок расширен до 6 float: view_size + z_range + ground_params(halfH); z считается в VS из world-атрибута) — далёкий высокий клиф больше не перекрывает ближнюю плоскую землю, а подводная полка всегда проигрывает плоскости. Порядок мира в `WorldRenderer::render`: плоская земля → 3D-проходы (raised, объединённый cliff, cyclopean) → texture2d-покрытие → сетка → спрайты. Texture2d идёт **после** 3D, чтобы блендиться с тем, что реально под ним уже нарисовано (пляж/земля/вода), а не выгрызать альфой дыру в геометрии, нарисованной позже: его пайплайн — `compare=LESS_EQUAL` против опубликованной глубины **без своей записи** (веера клеток стыкуются встык, painter-union не нужен), а кавер-лифт `kTextureCoverLiftPx` (24 px — выше верха mask3d-пляжа ~6–13 px, ниже любого поднятого уровня ~96+ px) по-прежнему арбитрирует исход. Побочка незаписи глубины покрытием: над открытой водой water-surface проход тонирует его каустикой (глубина под ним — вода; над полкой/землёй — нет), зато и покрытие над подводной полкой корректно «утоплено». Сетка рисуется после покрытия с `compare=LESS_EQUAL` + depth write: ε-сдвиг `kGridZBias` держит её поверх ко-планарной земли, покрытие глубину не пишет, и сетка остаётся видимой поверх него; поднятое 3D сетку прячет (его z ближе), подводное ей проигрывает (читается «под водой»), а записанный сеточный z (плоскость−ε) заставляет water-surface проход отбрасывать её пиксели. **Ко-планарные тайлы земли глубину НЕ тестируют:** у ground-пайплайна `compare=ALWAYS` + depth write ON — атласные тайлы перекрываются на ±2 ряда и обязаны миксоваться painter-union; интерполированный z двух квадов в одном пикселе различается на ~1 ulp (zFar≈1e5 съедает float32-точность до кванта depth-буфера), и LESS_EQUAL между ними детерминированно z-fight'ится: квад-победитель со своими альфа-дырками пропускает воду («трава рвётся полосами»). Записанной плоскости достаточно для поздних проходов (3D выигрывает высотой, подводное проигрывает). Растворение под водой — в cliff-FS: фрагмент с `v_world.y < 0` получает `alpha = smoothstep(−underwaterFade, 0, y)` (params3.z), бленд SRC_ALPHA/1−SRC_ALPHA включён в cliff-пайплайне (при alpha=1 вывод бит-в-бит прежний, Qt-композит FBO не страдает — фон непрозрачен); параметр `CliffShading::underwaterFade` per-asset (JSON + конвертеры обоих доменов + QML-слайдер TechSettings). Поверхность воды — `WaterBackground` в шелле редактора (клиент — тёмный clear), два прохода: непрозрачный fullscreen-фон до мира (world-anchored каустика) и **water-surface проход после мира** (свой pass в `MapRenderItem::render`, только color-attachment): FS сэмплит depth-буфер мира как текстуру, по общей z-формуле восстанавливает глубину видимой геометрии под плоскостью 0 (z-метрика считает y дважды — screen-lift + depth-член, поэтому уровень = (1+kDepthHeightFactor)·heightScale·kZScale клип-z) и блендит каустику с alpha, растущей от 0 на урезе до непрозрачной на глубине (`surfaceFadeDepth`/`surfaceMaxAlpha`); фрагменты ближе плоскости (поднятая геометрия и сетка с её kGridZBias) дискардятся — сетка читается плавающей на воде, плоская земля (y=0) не тонируется вовсе. **Грабли:** (1) GL хранит depth как (clipZ+1)/2 — сравнивать и мерить глубину надо в stored-пространстве (разница ×2 к клип-единицам), иначе вода зальёт вообще всё; (2) сэмплить depth24 в sokol можно только объявив `SG_IMAGESAMPLETYPE_UNFILTERABLE_FLOAT` + NONFILTERING-сэмплер (FLOAT требует filterable-формат, DEPTH — comparison-сэмплер, который отдаёт результат сравнения, а не значение); (3) текстуру нельзя биндить в том же pass, где она attachment — поэтому отдельный pass. Покрытие — `src/tests/render_core/depth_levels_test.cpp`.
- **Альфа-канал в sokol-бленде (грабли):** при `blend.enabled=true` и невыставленных alpha-факторах sokol дефолтит в `src=ONE, dst=ZERO` — альфа **заменяется**, и полупрозрачный фрагмент затирает непрозрачность уже записанного под ним (в редакторе FBO с alpha=0 прокомпоновывается Qt'ом в QML-фон: плоская трава рисовалась «чёрными ромбами» поверх воды). Всем world-проходам с блендом выставлены явные `src_factor_alpha=ONE, dst_factor_alpha=ONE_MINUS_SRC_ALPHA` (классический over). `mesh_preview_renderer` сознательно не тронут — превью в палитре хотят прозрачный фон. Сюда же: у sprite/атласных PNG прозрачные тексели часто несут белый matte → LINEAR-фильтрация тянет белесый ореол; лечится в `render_core/image_loader.cpp` (`bleedTransparentRGB` — Voronoi-fill RGB прозрачных текселей из ближайших видимых, альфа не трогается).
- **Кисти ландшафта (`LandscapePencil` и наследники):** `stroke()` красит линию нод Брезенхэмом между событиями мыши батчем через `MapAuthoring::applyLandscapeUpdates` — раньше красила одну ноду на событие, и быстрый росчерк оставлял дыры в нод-поле → дырявые частичные тайлы (вторая причина «травы полосами»).
- Превью ассета в палитре редактора идёт через `AssetImageProvider` (`image://assetImages/<uuid>`), а наполняет кэш `SliceAsset::registerImages`: у атласных типов индекс 0 — это тайл 0 атласа, у безатласных (cliff3d/stone3d/cyclopean3d/texture2d/tech3d) атласа нет, и под индексом 0 регистрируется `thumbnail.png` из бандла. Без этого ячейка в палитре рисуется пустой (виден только заголовок), и ассет выглядит «отсутствующим» — новым безатласным типам обязательно класть `thumbnail` в `index.json`.
- QML и C++-логику держать разделёнными; связывать через Qt properties/signals/slots.
- Чистые сериализуемые данные — в `game_data` (без Qt); `QObject`-обёртки — только для view-логики в редакторе.
- Перед архитектурными или продуктовыми решениями сверяться с `docs/ROADMAP_VISION.md` и `docs/TECHNICAL_STACK.md`.

## Сборка (macOS, CMake + vcpkg)

macOS-флоу — Xcode generator + CMake Presets, та же `_intermediate_64`, триплет `arm64-osx`.

- Конфигурация: `./build_mac.sh` (обёртка над `cmake --preset macos`). Первая конфигурация собирает все vcpkg-зависимости (включая Qt) — занимает ~1–2 часа.
- Сборка из CLI: `cmake --build --preset macos-debug --target EpicMapEditor`.
- **CLion:** пресет `macos-clion` (Ninja, `_int_clion`, Debug + compile_commands) — CLion не поддерживает Xcode-генератор основного пресета. `macos-index` (`_intermediate_ide`) оставлен под индексацию Serena/clangd, в IDE его не используем.
- Бинарники: `_intermediate_64/src/apps/<App>/Debug/<App>` (command-line executables, не .app).
- Smoke-проверки: `EpicGameClient --smoke`, `EpicMapEditor --smoke`; юнит-тесты — `_intermediate_64/src/tests/Debug/neverwhere_tests`.
- **RttrPlayground на macOS не собирается** (vcpkg-порт rttr не поддерживает osx; его CMakeLists возвращается сразу на не-Windows).

Платформенные особенности порта:

- **Рендер-бэкенды:** редактор и EcsPlayground — принудительный `SOKOL_GLCORE` (Qt OpenGL контекст), standalone-приложения — `SOKOL_METAL` (выбор в `render_core/sokol_config.h` и main.cpp по `__APPLE__`). Для GLCORE на macOS обязателен core profile: `QSurfaceFormat` 4.1 Core до создания `QApplication` (см. `main.cpp` редактора), иначе Qt даёт legacy 2.1 контекст и sokol падает на `sg_setup()` в Debug.
- **Шейдеры:** у `render_core` и playground-рендереров три варианта исходников — GLSL / HLSL / MSL; Metal-ветка выбирается по `sg_query_backend() == SG_BACKEND_METAL_MACOS` (runtime) или `#elif defined(SOKOL_METAL)` (compile-time). Единого `SG_BACKEND_METAL` в sokol нет.
- **sokol_app на macOS** требует Objective-C++: `main.cpp` standalone-приложений компилируется как ObjC++ через макрос `nw_configure_sokol_app(target)` в `cmake/utils.cmake` (там же линковка `Cocoa/QuartzCore/Metal/MetalKit`; на Windows — `d3d11/dxgi`). Все новые standalone sokol-приложения — через этот макрос.
- **glad нельзя включать в TU с `SOKOL_IMPL` на macOS и Linux** (и вообще вместе с Qt GL-заголовками): sokol_gfx/qopengl тянут системные GL-заголовки (`<OpenGL/gl3.h>` на macOS, `<GL/gl.h>` на Linux), которые конфликтуют с glad-макросами. На macOS это compile-time конфликт, на Linux — коварнее: glad'овский `__gl_h_` guard молча блокирует `<GL/gl.h>`, и sokol зовёт GL через незагруженные glad-указатели (NULL) → SIGSEGV в `sg_setup`. На Windows спасает встроенный лоадер sokol (его макросы перекрывают glad'овские). GLCORE-бэкенд линкуется `-framework OpenGL` на macOS и `OpenGL::GL` на Linux.
- **Ресурсы:** `baseDataPath` в `core_context.cpp` ищется вверх от cwd (repo root, `_intermediate_64` — оба сработают); хардкода абсолютных путей нет.
- **Код-подпись:** ad-hoc (`CODE_SIGN_IDENTITY "-"` в `nw_add_app_sources`, post-build `codesign -f -s -` у EpicMapEditor) — пустая identity в Xcode невалидна для CLI-таргетов.
- После обновления Xcode **сбрасывать CMake-кэш** (`cmake -U LIBRESOLV` или чистый `_intermediate_64`): `find_library` кэширует пути внутрь старого SDK.

### vcpkg и зависимости

- vcpkg подключён как submodule (`toolchain/vcpkg`). **Не патчить** `toolchain/vcpkg` напрямую.
- Зависимости — через `vcpkg.json`.
- Для overlay-фиксов — `vcpkg_overlays/ports`; путь уже подключён в `CMakePresets.json` через `VCPKG_OVERLAY_PORTS`.
  - Например, Sokol подключён через overlay, чтобы держать `util/sokol_imgui.h` совместимым с актуальным Dear ImGui из vcpkg.
- При добавлении зависимости: обновить `vcpkg.json` → `find_package(...)` → прилинковать импортированный target в `LIBS` у соответствующего `nw_add_...`.

#### Binary cache (сетевой)

Все configure-пресеты в `CMakePresets.json` читают зависимости из общего HTTP binary cache (`https://cache.blackbox9.cc:9443`, readwrite) — чистая конфигурация после wipe `_intermediate_64` восстанавливает весь closure за ~2 минуты вместо полной пересборки. Авторизация **не хранится в репозитории**: пресет подставляет `$env{NEVERWHERE_VCPKG_CACHE_AUTH}`, поэтому на каждой машине нужен экспорт (shell profile / CI secret):

```bash
export NEVERWHERE_VCPKG_CACHE_AUTH="Authorization: Basic <base64(user:pass)>"
```

Переменная не установлена — не страшно: конфигурация не падает; чтение из кэша работает и без авторизации (GET на сервере открыт, проверено 2026-08-03 из LAN — см. `docs/VCPKG_CACHE.md`), но push не пройдёт: машина сможет потреблять кеш, но не пополнять. Подстановка `$env{}` работает только при запуске configure через пресет (`build_mac.sh`/`build_linux.sh`/`cmake --preset ...`); ZERO_CHECK-переконфигурация изнутри IDE берёт env процесса сборки.

### Индексация для IDE/clangd (Serena MCP, clangd LSP)

Основной флоу — Visual Studio generator, который **не** умеет эмиттить `compile_commands.json` (это ограничение CMake, не баг). Для Serena/clangd есть отдельный Ninja-preset, который только конфигурирует (не собирает).

- **Preset:** `ide-index` в `CMakePresets.json` — Ninja generator, `CMAKE_EXPORT_COMPILE_COMMANDS=ON`, отдельный `binaryDir = _intermediate_ide`.
- **Обёртка:** `generate_compile_commands.bat` — вызывает `vcvars64.bat` (Ninja не находит MSVC сам), конфигурит, копирует/симлинкает `compile_commands.json` в корень репо.
- **Запуск:** `generate_compile_commands.bat` (или `--clean` для полного ребилда кэша).
- **Когда перегенерировать:** после добавления/удаления исходников, изменения compile-флагов или `vcpkg.json`. После правок в существующих файлах — **не нужно** (clangd читает флаги из `compile_commands.json`, а не из самих исходников).
- `_intermediate_ide/` и `compile_commands.json` в `.gitignore` — это локальные artefacts.

Без `compile_commands.json` Serena работает на структурном parse (видит имена, но не типы), и `get_diagnostics_for_file` выдаёт ложный шум (`'QObject' file not found`, `Unknown type name 'Q_OBJECT'`). С ним — полноценная индексация: чистая диагностика, полные references, type-aware навигация.

Платформенные особенности порта:

- **Рендер-бэкенд:** `SOKOL_GLCORE` везде (выбирается в `render_core/sokol_config.h` по умолчанию на не-win/apple/emscripten); шейдеры — GLSL-варианты. - **sokol_app на Linux** идёт через X11 (на Wayland-сессии — XWayland): макрос `nw_configure_sokol_app(target)` линкует `X11 Xi Xcursor GL dl pthread m`.
- **GLCORE в Qt-приложениях** (EpicMapEditor, EcsPlayground) требует `OpenGL::GL` на линковке — sokol_gfx грузит GL-функции через `glXGetProcAddress`.

- `compile_commands.json` в корне — симлинк на `_int_linux/compile_commands.json` (preset сам эмиттит, отдельный index-preset не нужен).
- **RPC `screenshot` под Wayland отдаёт чёрное** ( `_cmdScreenshot` использует `QScreen::grabWindow` — X11-протокол, а под XWayland контент живёт в Wayland-буферах). **Штатный обход:** запускать редактор под `xvfb-run` (пакет `xvfb` установлен) — там настоящий X11-сервер и grabWindow честный:
  `xvfb-run -a -s "-screen 0 1920x1080x24" _int_linux/src/apps/EpicMapEditor/Debug/EpicMapEditor`
  Рендер внутри Xvfb — software (llvmpipe), кадры медленнее, чем на GPU; для скриншотов/авторинга через RPC этого хватает. На сами авторинг-операции (`set_tile`/`set_landscape`/…) платформа не влияет.

### Отладка падений через debug-MCP (`neverwhere-debug` / `neverwhere-debug-macos`)

MCP-сервер из `tools/debug_mcp/` — единый `debug_*` контракт, backend по платформе: **cdb** на Windows (`neverwhere-debug`, лаунчер `tools/run_mcp_server.ps1`) и **LLDB** на macOS (`neverwhere-debug-macos`, лаунчер `tools/run_mcp_server.sh`). Подключены в `.mcp.json`, запускаются автоматически вместе с IDE; нерабочая на данной ОС запись просто не стартует. Зависимости: `mcp>=1.0` (см. `tools/debug_mcp/requirements.txt`); на macOS — LLDB из Xcode (`xcrun lldb`), venv создаётся лаунчером при первом запуске.

**Принцип debugger-first (cdb-first):** при падении/ассерте/неверном рантайм-значении — сначала **доказательство через MCP** (`debug_*`), не фикс по стектрейсу из лога.

**Базовый flow для краша EpicMapEditor:**
1. `debug_self_check` — проверить, что отладчик найден, exe и символы на месте.
2. `debug_session_start(exe_target="EpicMapEditor")` — запустить inferior (или `debug_process_find(name_query="EpicMapEditor")` → `debug_session_start(process_id=<pid>)` для attach к уже бегущему).
3. `debug_run_until_stop` — гонять до падения/брейкпоинта.
4. `debug_stack_get` / `debug_scopes_get` / `debug_expression_eval` — стек, локали, выражения в точке сбоя. Реальная точка — **первый проектный фрейм** (под `repo_root()`), не верхний CRT/SEH-трамплин.
5. `debug_session_stop` — закрыть сессию.

**Разрешение exe-таргета:** Windows — `_intermediate_64/<config>/<target>.exe`; macOS — `_intermediate_64/src/apps/<target>/<config>/<target>` (по умолчанию `EpicMapEditor`, конфиг `Debug`). Override: env `NEVERWHERE_DEBUG_EXE` / `NEVERWHERE_DEBUG_EXE_TARGET` / `NEVERWHERE_DEBUG_EXE_CONFIG`, или пин через `debug_set_active(cmake_target="...")` → `.zcode/debug_active.json`.

**cdb search order (win):** env `CRASH_ANALYSIS_DEBUGGER_PATH` → Windows Kits (`C:\Program Files (x86)\Windows Kits\10\Debuggers\x64\cdb.exe`). В `.mcp.json` путь уже прописан.

**macOS-особенности:** SIGSEGV/SIGABRT приходят как Mach-exception (`EXC_BAD_ACCESS`) — смотри `stop_event.exception.signal_equivalent`; attach только к своим процессам (SIP); DWARF в бинаре, отдельных символов не нужно; smoke backend'а без MCP — `tools/debug_mcp/smoke_lldb_worker.py`. LLDB backend живёт в `lldb_backend.py` + `lldb_worker.py` (worker на системном python3 3.9, т.к. SB API собран под cp39). Дополнительно: `debug_crash_report` — полный слепок при останове за один вызов (стеки всех потоков, project_frame + scopes + `this`, регистры, хвост лога inferior), `debug_variable_expand` — дрилл-даун по вложенным структурам (`this->layers`, `(*this).map`); на Windows оба пока `not_supported`.

**Post-mortem (.dmp):** `debug_crash_dump_analyze(dump_path)` — анализ готового дампа (Windows). Сейчас в neverwhere нет C++ хука для записи дампов при падении (это отдельный следующий шаг: `MiniDumpWriteDump` в `main.cpp` + `CRASH_DUMP_DIR`).

Полный список инструментов и контракт — `debug_contract_get`. Детальная методичка (flow, gotchas, first-chance exceptions, чек-лист) — `docs/debugging.md`.

Операции:

### Shadertoy

`src/landscape_playgrounds/Shadertoy` — универсальный хост для shadertoy-референсов из `docs/reference/shadertoy` (дорога «демка → кубик с материалом → SDFGeneratedLandscape → инструмент → редактор»; это шаг 1–2). Демки подхватываются без перекомпиляции: пассы по именам (`Image.glsl`, `BufferA..D.glsl`, `Common.glsl` инжектится во все пассы), текстуры `textures/iChannelN.(png|jpg)` биндятся по имени файла, multi-pass граф — опциональный `shadertoy.json` (формат — в `docs/reference/shadertoy/README.md`). ImGui-список демок, hot-reload (R / кнопка; ошибки компиляции — в окне), превью «кубик с материалом» (Image-пасс на вращающемся кубе), `--list` / `--demo "name"` / `--cube` / `--dir` / `--shot <png>` / `--scale <0.1..1.0>` (рендер в пониженном разрешении с апскейлом — реймарч-демки на 2x-DPI фреймбуфере 2560×1440 иначе ползут; время кадра линейно по пикселям, GPU-bound) / `--smoke` (прогон всех демок по 30 кадров с TEST PASS/FAIL).

- **Бэкенд — осознанное исключение:** `SOKOL_GLCORE` на всех desktop-платформах (не Metal на macOS): демки — single-source GLSL `#version 330` + shim (iResolution/iTime/iMouse/…/iChannel0-3), портить каждую на 3 диалекта нерентабельно. На MSVC — `opengl32`, на macOS — `-framework OpenGL` (в CMakeLists поверх `nw_configure_sokol_app`).
- **Заголовки с `#include <sokol_gfx.h>`** (ShadertoyRuntime.h, CubePreview.h) должны включаться в TU **до** `#define SOKOL_IMPL` — в этой версии sokol impl-секция живёт вне include-гарда и двойное включение с SOKOL_IMPL даёт redefinition-ошибки (конвенция как в TextureBlendLandscape).
- **macOS-особенность GLSL:** Apple-компилятор резервирует `noise1..4` (legacy built-ins) — shim переименовывает их макросами в преамбуле; `pow(vecN, float)` нестандартен (ANGLE терпит, Apple — нет), правится в исходнике демки.
- Пайплайны: буферы — RGBA16F (feedback-точность), Image — формат свапчейна (и image-target для куба в нём же); все пассы с общим depth-attachment'ом, чтобы один depth-формат подходил везде.

### StoneCube + stone_gen

`src/landscape_playgrounds/StoneCube` — инкубатор генератора «кубика из камней» по принципам iq'шной демки Voronoi - rocks (`docs/reference/shadertoy`): SDF = round-box + bulge внутри voronoi-ячеек (`clamp(k*(F2-F1))`, борозды по границам), fbm-деталь + bump, AO + soft shadow, ground plane с тенью, orbit-камера (LMB — вращение, RMB — пан, колесо — зум), ImGui-параметры (Shape/Detail/Look, кнопка New seed). Дорога развития: C++-двойник SDF → меш через surface-nets (`highground_core`) → SDFGeneratedLandscape → редактор.

`src/libs/stone_gen` — no-GPU либа генератора и пекарни (паттерн `highground_core`): `StoneSdf` (C++-двойник, каноничен; GLSL в плейграунде — look-референс) → `generateMesh` (sample → `regularizeSigns`/`extractSurfaceNets` через `cliff::ScalarFieldView` — обобщённая точка входа в `surface_nets.h`, клифы делегируют в неё) → `bakeTextures` (CPU-растеризатор в UV-пространстве: `albedo.png` rgb=тинт+moss+groove, a=AO; `normal.png` object-space) + `writeObj`/`writePng`. UV — атлас 3×2: box-проекция по доминантной оси нормали, у каждой из 6 граней свой тайл (проекция всех граней в общий [0,1] наслаивает их данные бейка друг на друга) + дедуп швов (`splitSeamVertices`: клонирует углы треугольников, чья грань (ось+знак) не совпадает с гранью треугольника, иначе они тянутся через весь атлас). Покрытие — `src/tests/stone/stone_gen_test.cpp` (watertight, бейк, экспорт).

Там же (`stone_field.h`) живёт `StoneField` — перенос каменного принципа на хайграунд по нодам (контракт как у `cliff::CliffField`): сетка нод → плита-плато (база `cliff::CliffField::evalBase`) → voronoi-карвинг StoneCube (`clamp(k*(F2-F1))` bulge, борозды по границам ячеек, маской прижат к поверхности плиты) + fbm → surface nets. По умолчанию включён flat-top с rim-стичем: рельеф (карвинг + fbm + groove-атрибут шейдинга) гасится по Y-компоненту нормали базовой плиты (`flatTop`/`flatTopLo`/`flatTopHi`), но в полосе у кромки (`rimWidth`, в ~мировых единицах — `(edgeRadius-d2)/|∇d2|`, т.к. d2 — сжатый псевдо-SDF, а не дистанция) стыковка структурная: камни не срезаются, а заворачиваются на верх (`rimBulge`), устья борозд/провалов вдавливают верх вниз (`rimNotch`); середина верха остаётся точно плоской. Численные градиенты — общий 7-таповый `StoneField::sampleBase`; двухаргументный `CliffField::evalBase(p, d2)` публичный. Используется кистью «Stone 3D» в SDFGeneratedLandscape (тот же кэш/debounce, что у «Cliff 3D», свои параметры `StoneFieldParams` и серая каменная палитра через per-layer shading override; выступы-валуны над плоскостью верха красятся палитрой стены — порог plane-Y в поле-юниформе `params1.w` общего cliff-шейдера, 0 = выкл, клиф-слой не затронут; впадины кромки остаются палитрой верха; градиент «камень к кромке» на плоском верхе идёт per-vertex rim-атрибутом (`StoneField::rimFactor` — близость к стене из `rimStitch`, без гейта по topness: стены шейдер сам отсекает нормалью; транспорт — `cliff::ScalarFieldView::rimFactor` → `cliff::MeshVertex::rim`, сила — юниформа `params2.y`, ширина — общий `rimWidth`), верх опционально заливается тайлящейся текстурой (`top_tex`, world-space UV по `p.xz`, сила/тайлинг — `params2.zw`; в плейграунде грузится `resources/textures/grass.png`, при промахе — палитра); pcg3d/voronoi/fbm — бит-в-бит дубли `stone_sdf.cpp`, StoneSdf не трогаем).

- Playground: режимы Raymarch | Mesh (запечённые текстуры) | **Procedural** — тот же меш, но материал (voro-тинт/мох/fbm-бамп/AO/soft shadow) считается попиксельно из world-позиции, без UV и текстур (подход `cliff_renderer`; look-параметры живые, ребилд меша только по shape-параметрам, debounce 0.3 с). Процедурный и реймарч режимы рендерятся в scaled offscreen target (тяжёлые попиксельные шейдеры на 2x-DPI). Bake 256/512/1024, Export в `bake_out/`, CLI `--smoke` / `--shot` / `--scale` / `--seed` / `--mesh` / `--proc` / `--bake <dir>`.
- Грабли (по опыту): naive surface nets террасит на крутых voronoi-бороздах — лечится 3-tap блюром сэмплов (`MeshParams::blurPasses`); bump-градиент fbm десятки единиц — без кепа `g/(1+|g|)` запечённая normal-map выходит радужным шумом; на бейке stencil градиента ~1–2 текселя (low-pass); GLSL 330 `const float x = <uniform-выражение>` не компилируется.
- Шейдерные: полосы «шторки» на реймарче — это квантование глубины попадания (raymarch banding), лечится секант-уточнением хита + широким stencil нормали (0.004), а НЕ более мелким eps; `fract(sin(x)*43758)` на больших аргументах даёт направленные полосы — в генераторах использовать целочисленный pcg3d-хэш (GLSL и C++ дублируют друг друга бит-в-бит).
- stb-имплементации (STB_IMAGE_..._IMPLEMENTATION) — в одном TU на бинарь: для `stone_gen` это `stone_bake.cpp`, приложения либу линкуют и не повторяют.

### ShapemlPlayground + shapeml_ref (ShapeML, GPL3v3)

`src/apps/ShapemlPlayground` — обозреватель возможностей [ShapeML](https://github.com/stefalie/shapeml) (shape grammars / CGA-подобное процедурное моделирование: extrude/split/roof по straight skeleton). Список `.shp`: сначала собственные грамматики из `src/apps/ShapemlPlayground/grammars/` (`stone_wall.shp` — каменная кладка с перевязкой/цоколем/капителью: trimPlane-фаски «подушей», вероятностные finish-правила цвета, выпадающие камни; `christmas_tree.shp` — казуальная ёлочка: ствол + ярусы фасеточных конусов с рампой зелени по `index`, кольца шаров через `repeat`+`rotateY` вокруг оси, звезда — `polygon`+`extrude`, снежная подложка; `fence.shp` — модульная ограда «казуальная готика»: каменные столбы из крупных валунов (стопка pillow-bevel блоков с yaw-джиттером и случайными сколами-сечениями, двухступенчатый цоколь, мох у подножия) + черепичная крышка (тёмный 4-конус-сердечник + 2×2 сланцевые плитки на скат с реальной толщиной, укладка внахлёст; **4-сегментный coneFlat рождается с гранями по осям scope — поворачивать на 45° НЕ надо**) + кованая секция (два рельса, прутья с копьями через один по `index % 2`, кольца-торы между прутьями, лёгкий случайный наклон прутьев), состаренный металл — железо/медь-вердигрис переключаются `param metal` (финиали столбов — тот же металл: шар у обычного, шпиль у углового/высокого), акценты ржавчины/голой меди вероятностными правилами; `param piece` выбирает деталь под экспорт: столб / угловой столб / секция / демо-прогон; все ручки — `param`), затем стоковые из `external/shapeml/grammars` (override `--dir`), живые контролы `param`-параметров грамматики, seed, auto-derive с debounce 0.3 с, orbit-камера (как StoneCube), экспорт OBJ их `Exporter`'ом (в `tmp/shapeml_export/`). CLI: `--smoke` (parse+derive всех грамматик директории, TEST PASS/FAIL; ~1.5 мин в Debug — stress-грамматики `test_noise_2D` (65k листьев) и `test_noise_3D` (247k листьев / 5.9M вершин, ~5 ч в Debug) пропускаются, для них — явный `--grammar`) / `--shot` / `--seed` / `--grammar <имя|путь>`. Рендер — минимальный sokol-пайплайн (GLCORE-исключение, шаблон StoneCube): цвет материала × diffuse-текстура (stb_image, белый 1×1 fallback), lambert + hemisphere ambient, дравы сгруппированы по текстуре. Мост к библиотеке — `GrammarHost` (единственный TU с shapeml-инклюдами, pimpl): `Parser::Parse` (**у них true = ошибка**; base_path/file_name выставляет сам — ассеты грамматик резолвятся от файла грамматики) → `Interpreter::Init/Derive` (обязательно с world-octree `Octree(Vec3::Zero(), 1000)` — occlusion-грамматики вроде castle.shp крашатся без него) → листья через `LeafConstVisitor` (фильтр `terminal && visible && mesh && !Empty`) → `FillRenderBuffer` + `MeshWorldTrafo`/`MeshNormalMatrix` (меши в unit-space 0..1, кэшируются по указателю — инстансы делят меш).

Библиотека — submodule `external/shapeml` + обёртка `src/libs/shapeml_ref` (свой CMakeLists: их билд несовместим с CMake 4.x — `cmake_minimum 3.0`, а viewer/glfw нам не нужны; собираются только core + surface_mesh, C++17, `-w` + force-include `cstdint` — их `vector_types.h` полагается на транзитивный `<cstdint>`, пропавший в GCC 13+). **Лицензия GPL3v3:** `shapeml_ref` линковать ТОЛЬКО в ShapemlPlayground (внутренний инструмент, не распространяется); в EpicMapEditor / EpicGameClient / общие libs — нельзя, статическая линковка GPL делает производный бинарь GPL при распространении. Грабли: `Bool` — макрос X11 (`#define Bool int`, течёт из sokol_app.h) — в enum плейграунда значение названо `Boolean`. Сам таргет ShapemlPlayground тоже поднят на C++17 (не проектный C++20): `GrammarHost.cpp` тянет shapeml-заголовки с бандленным Eigen 3.3.7, а его `std::result_of` выкинут из libc++ в C++20 — на macOS без этого не собирается (на MSVC `result_of` ещё жив). В грамматиках: splitX/Y/Z требуют меша на шейпе (ставить `quad` перед split); `color()` обязан стоять inline в правиле, закрывающемся терминалом — «голое» color-правило в середине op-string теряет материал; `extrude()` растёт в +y локального scope, поэтому стены строятся «лёжа» и ставятся `rotateX(-90)` (+`rotateZ(180)` лицом к дефолтной камере); подложки нельзя оставлять coplanar задним граням камней (z-fighting) — утапливать глубже. Повороты scope (`rotateY` и т.п.) крутят вокруг **origin** scope (мин. угол бокса), а не вокруг центра — для колец/спиралей сначала `translate(size_x*0.5, ·, size_z*0.5)` origin'ом на ось, потом `repeat` + `rotateY(360·index/n)`; примитивы вписываются в scope-бокс (конус/сфера по границам), 2D-примитивы (`quad`/`polygon`) лежат в локальной плоскости x–z; `repeatNoPush` инкрементит атрибут `index` (0-based), на него можно вешать условные правила (`:: (index == 0)`) — так делается рампа цветов по ярусам.

### HighgroundWithEffects: стыковка хайграунда с землёй

`src/landscape_playgrounds/SDFGeneratedLandscape` раздвоён: **SDFGeneratedLandscape** — чистый стенд отладки генерации геометрии (состояние до эффектов стыковки), **HighgroundWithEffects** — форк с эффектами стыка (общее солнце, контактное AO, shadow map, материалы стыка, grass underlay; также HiDPI-фикс сцены в точках). Геометрические кисти («Cliff 3D», «Stone 3D») и конвейеры одинаковы в обоих; эффекты — только в Effect-версии.

У SDFGeneratedLandscape есть плоский слой «Texture 2D»: ландшафт из любой тайлящейся текстуры (`resources/textures`, подхват всех png/jpg на старте; все файлы пакуются в один texture array — `AtlasRenderer::buildTilingTextureArray`, билинейный ресемпл к общему размеру, слой массива = индекс файла). Текстура **не нарезается** на per-tile кусочки атласа (кусочки не сойдутся на стыках) — цвет сэмплится непрерывно в мировых (field) координатах (`v_world * tiling`, REPEAT-сэмплер, как `top_tex` у клифов), а Yellow-маска Flat-атласа работает только stencil (alpha), без рельефа кромок — поверхность читается как одно целое (у самого Yellow 2D тёмные окантовки ромбов — осознанный технический арт). В палитре каждая текстура — отдельный инструмент, сгруппированный под «Texture 2D», чтобы было видно, что слой один: нода хранит тег текстуры (`LandBrush::setNode(node, on, tag)`, tag = слой массива + 1, 0 = untagged), перекраска ноды другой текстурой вытесняет старую. Переходы между соседними текстурами — плавные: клетка тесселлируется веером из центра в 4 угловые ноды (ромб, `appendTileFan`), углы несут one-hot веса кандидатных текстур клетки (`LandBrush::cellTextureBlend`, ≤4 кандидатов; соседние клетки непрерывны, т.к. делят ноды на общем ребре), а FS миксует слои массива по интерполированным весам с органичным fbm-вобблом (гейт `w*(1-w)` — чистые интерьеры не трогает) и sharpness-экспонентой. Тем же веером растворяется и внешний контур региона: per-vertex fill (1 у on-ноды, 0 у off) интерполируется, альфа = smoothstep вокруг iso 0.5 (та линия, где раньше резала маска) с тем же fbm-вобблом — жёстких ступенек на границе с пустотой нет; ширина пера — слайдер edge fade (`blend_params.w`, 0 = жёсткий срез). Плоские не-текстурные слои (Grass/Yellow/силуэты клифов) идут квадом с fill=1 и не меняются. Все blend-параметры — живые юниформы (`blend_params`, слайдеры у слоя). Мажоритарное `cellTagAt` осталось для логики/фолбэка, рендер идёт через бленд; untagged-клетки (нулевые веса) падают в маску-only фолбэк. Реализация — world-UV режим плоского прохода `AtlasRenderer` (юниформы `tex_params`/`blend_params`; у мультитекстурного слоя `PaintLayerView::multiTexture` — один range на слой); CLI `--tex-nodes=` / `--tex-tiling=`. `--shot` там портируемый (glReadPixels, как у Effect-версии); захват ждёт устаканивания кэшей (ни один field-слой не `pending` после дебаунса) + 1 с wall-time, с фолбэком на 120 кадров — слепой счётчик кадров на llvmpipe под xvfb растягивал ожидание на минуты, а на быстрой машине кадры пролетали быстрее дебаунса 0.3 с и 3D-меши не успевали в кадр.

У SDFGeneratedLandscape есть учебный слой **«Box 3D»** — минимальный семпл поля по общему контракту: `boxfield::BoxField` (`BoxField.h/.cpp` в плейграунде, как TechOutlineField-форк) строит по одному axis-aligned боксу на закрашенную клетку (клетка занята, если горит любая из 4 угловых нод — правило `cellNonEmpty` из tech_field); `eval` — `min` по боксам (CSG-объединение), соседи сливаются только при `fill = 1` (общая грань), при `fill < 1` между клетками честные щели; `blurPasses = 0` — чёткие грани. Никакой интерполяции и shading-каналов (groove/rim пусты) — годится как отправная точка для экспериментов с формой: правится только `eval`. Свои params/height scale/CLI (`--box-nodes=`, `--box-fill=`), тот же кэш/debounce, что у остальных field-слоёв; smoke-сценарий — в `PlaygroundSmokeTest.cpp` (watertight при fill 1/0.6, пинч диагональных клеток для regularizeSigns, верх на boxHeight).

Следующий учебный слой — **«Circle 3D»**: `circlefield::CircleField` (`CircleField.h/.cpp` там же) рисует по вертикальному цилиндру (`max(radial, axial)` — точное CSG-пересечение бесконечного цилиндра со slab'ом `0..height`) вокруг каждой закрашенной **ноды** («круг вокруг вершины»), а клетка, у которой горят **все 4** угловые ноды (противоположный конец any-corner правила BoxField), становится полностью поднятым параллелепипедом `[cx,cx+1]×[0,height]×[cz,cz+1]` — тем же box-SDF с fill=1, поэтому соседние полные клетки сливаются бесшовно. `eval` — общий `min` по цилиндрам и боксам в радиусе `max(1, ceil(nodeRadius))`; дефолтный `nodeRadius = 0.55` чуть перекрывает соседние круги (сливаются в один блоб), а центр полной клетки (~0.707 от углов) добивает именно бокс — в smoke это различение проверяется отдельными `eval`-пробами. Padding авто-поднимается до `nodeRadius − 1 + 2·cellSize`, чтобы слайдер радиуса не вытолкнул F≤0 на границу поля. Свои params/height scale/CLI (`--circle-nodes=`, `--circle-radius=`), тот же кэш/debounce; smoke — watertight, верх/низ, покрытие центра полной клетки, внутри/снаружи одиночного цилиндра.

Третий учебный слой — **«Mask 3D»**: `maskfield::MaskField` (`MaskField.h/.cpp` там же) поднимает 2D-силуэт слоя «Texture 2D» в плиту с покатыми краями: footprint — билинейная интерполяция per-node fill по 4 углам клетки, маска `fill ≥ 0.5` (та же iso-линия, что рисует текстурный слой: стены проходят середины рёбер on→off, полузакрашенные клетки — клинья, одиночная нода — маленький блоб), а поле — `max(y − top(s), −(y + hh), s − S)`, где `hh = height/2` и `s = sd(x,z)` — растрированный signed distance к изо-линии `fill = 0.5`, отрицательный внутри (8 текселей на клетку, дробный посев по линейному пересечению нуля на рёбрах текселей + двухпроходный chamfer (1,√2) — тот же приём, что у контактного AO в `scene_stitch`; в `eval` сэмплится билинейно, поэтому `eval` по-прежнему O(1) и цикл по окрестности не нужен), а `top(s)` — высота верха: `+hh` по ядру (силуэт spread=0 держит полную высоту) и линейный спуск до `−hh` поперёк spread-полосы шириной `S = spreadDistance`. Геометрия стоит половиной высоты ниже плоскости нод-сетки (y=0): плита занимает `±hh`, подошва юбки достаёт до `−hh` — та же «подводная» посадка, что у берегового tech-конвейера. Шейдерные fbm-воббл и alpha-фейд в геометрию не переносятся — контур становится чёткой стеной. Параметр `spreadDistance ≥ 0` (слайдер Spread, в клетках) — ширина «юбки» вокруг плиты: полновысотной геометрии за пределами ядра нет, край плиты скатывается градиентом высоты под сетку, а подошва юбки скругляется дугами на выпуклых углах (свойство честного distance field); при 0 формула точно сводится к плите `max(s, |y| − hh)` — вертикальная стена на той же изо-линии, что рисует текстурный слой. Нулевое кольцо бордера обязано быть шире spread — margin в `rebuildCliffCache` выводится как `1 + ceil(spreadDistance)`, иначе подошва юбки обрежется краем поля. Свои params/height scale/CLI (`--mask-nodes=`, `--mask-spread=`), тот же кэш/debounce; smoke — watertight (в т.ч. юбки), верх/низ на ±hh, интерьер без трещин на общих рёбрах, стена на середине on→off ребра, spread — полная высота ядра, градиент склона в двух точках, пересечение плоскости сетки посередине полосы, подошва на линии off-нод и скругление угла.

`src/landscape_playgrounds/SDFWithMaterialLandscape` — форк SDFGeneratedLandscape, схлопнутый до одной кисти «Mask 3D» (вычищены texture-array/blend machinery, остальные полевые слои и multiTexture; у `PaintLayerView` только `brush/atlas/cliffHeightScale/mask/maskParams/shadingOverride`, у плоских тайлов quad-вершина без весов, плоский FS — чистый atlas-маска, `--mask-nodes/--mask-spread/--mask-sink/--shot/--zoom/--center` сохранены). Маска форка параметризована погружением: `sinkFraction` (дефолт 0.5 = поведение базового плейграунда) — доля высоты плиты под плоскостью нод-сетки (будущая вода): плита занимает `−height·sink..+height·(1−sink)`, подошва юбки достаёт `−height·sink` (0 — дно на сетке, 1 — полностью под водой; слайдер «Sink below grid», дебаунс как у остальных mask-параметров). Назначение — инкубатор PBR-lite материала для field-слоёв на комплекте ambientCG Ground061 (CC0, карты лежат в `resources/textures/ambientcg/Ground061/`, см. README там же): в клиф-шейдер (все три диалекта, как всегда) добавлен материал — трипланар-альбедо (карты 2:1, V тайлится вдвое чаще — хелпер `matuv`), top-проекционные нормал-мапа (Tangent-фрейм вокруг геометрической нормали, NormalGL), AO (душит ambient-член) и roughness (душит spec), силы — юниформы `CliffFsParams::params2` (tiling/albedo/normal/AO) и `params3.x` (roughness): при нулевых силах шейдер бит-в-бит палитровый, каждый `paramsN` реально читается в GLSL (атомарность юниформ). Текстуры — 4 view-слота + общий REPEAT-сэмплер (LINEAR_MIPMAP_LINEAR + aniso×8: карты грузятся с полной CPU mip-цепочкой, `uploadSlotMipmapped` + 2×2 box в `buildMipChain` — без мипов минимизированная REPEAT-текстура на плоскости земли алиасится в шум; атласы мипами НЕ снабжать — тайлы перетекут друг в друга), placeholder'ы 1×1 (белый цвет, плоская нормаль (128,128,255), белые AO/rough), загрузчик `AtlasRenderer::loadMaterialMaps(dir, setName)`. Микрорельеф (displacement) — честная геометрия, а не parallax: CPU-растр `maskfield::ReliefMap` (loader `loadReliefMap`, grayscale 0..1) сдвигает изо-поверхность в `MaskField::eval` на `reliefDepth·(sample−0.5)·2` (REPEAT-билиней, тот же аспект 2:1). Растр при загрузке low-pass'ится повторным 2×2 box-халвингом с REPEAT-обёрткой до ~32×16: воксельная сетка физически не держит мелкую рябь исходной карты (строки ~0.03 мира = под воксель) — она превращалась в гравийный лумп-шум; геометрии остаются только дюны крупного масштаба, мелкая рябь живёт в нормал-мапе. Рельеф затухает к контуру ядра (`reliefFade` ~0.15 мира, smoothstep по −s) — стены и юбка держат чистый силуэт, дюны только на верхе плиты. Разрешение воксельное (дефолт cellSize 0.04 вместо 0.06), дефолты tiling 1.0 / depth 0.02 (CLI `--mat-tiling=` двигает и reliefTiling — дюны совпадают с рябью шейдера); при `reliefDepth=0` поле бит-в-бит гладкое; при `reliefDepth=0` поле бит-в-бит гладкое. Смена растра видна params-mempcmp'ом через счётчик `reliefVersion` (указатель в params + бамп при релоаде). UI — секция «Material (Ground061)» (силы мгновенны, relief-параметры дебаунсятся), CLI `--mat-dir=`/`--mat-tiling=`/`--relief-depth=`/`--mask-sink=`; материал выключается по умолчанию при промахе загрузки (силы зануляются в init). Smoke — рельефный блок: амплитуда ±depth на uniform-картах, билинейная проба на градиентной, watertight с рельефом; sink — пробы верха/низа по доле погружения. **Поле градуировало в библиотеку:** каноничный `mask::MaskField` теперь в `highground_core/mask_field.h` (+ `mask::reliefMapFromImage` — low-pass растра переехал туда же), в плейграунде остался лишь shim `MaskField.h` (`namespace maskfield = mask;`), а в редакторе поле живёт как mask3d-ассет (см. буллет выше).

`src/landscape_playgrounds/FencePathPlayground` — стенд для экспериментов с расстановкой забора и дорожек (инструментарий описывается по ходу, v1 — только сцена): сетка и камера портированы из SDFGeneratedLandscape — `GridRenderer` (оверлей-пасс AtlasRenderer без атласов и полевых слоёв: diamond-контуры клеток, hover-футпринт ноды с заливкой, node-marker, те же `bakedDepth`/`kZFar`/`kZScale`, color-шейдер в трёх диалектах, один dynamic-буфер на tri+line дравы, явный alpha-over в бленде) + `Camera2D`/`DiamondIsometry` из topology_core (RMB-пан, wheel-зум к курсору 0.15..3, вся сцена в точках, пиксели только в viewport/glReadPixels). Карта 24×24 клетки, hover по нодам (0..W включительно, бордерные ноды валидны — футпринт клипуется по клеткам). CLI `--shot/--zoom=/--center=/--no-ui/--smoke` (smoke — CPU-проверки раунд-трипов проекции и node/cell контракта topology_core, TEST PASS/FAIL). На macOS дефолт Metal; для `--shot` — opt-in `-DFPP_FORCE_GLCORE=ON` (шаблон SDFGL, после проверки вернуть Metal-дефолт).

**Z-буфер SDFGeneratedLandscape (грабли).** Глубина в плоском iso печётся из **ground-y** точки (`bakedDepth(fieldY)` в `AtlasRenderer.cpp`): field-y растёт к зрителю, поэтому при LESS_EQUAL + clear 1.0 ближнее — меньшее z. Анкер обязан быть **константой, а не от камеры**: cliff/stone/tech-стримы пекут z один раз при (дебаунсенном) ребилде меша, а оверлей пересчитывается каждый кадр — камеро-зависимый анкер расходится между ними, и панорамирования на одну клетку хватало, чтобы сетка перескочила из-под меша наверх (у HighgroundWithEffects та же константа `kZFar`/`kZScale`). Оверлей (сетка, hover-футпринт) сидит **на самой плоскости земли** — тот же `bakedDepth` от своего field-y, и это осознанно «поверхность воды»: высота фрагмента сдвигает его только **вверх** по экрану, т.е. на ряды **дальше** своего, поэтому поднятая геометрия всегда выигрывает у сетки, которую накрывает, а то, что висит **ниже** плоскости (стенки цокольной плиты, подводная нога Tech 3D Outline), уезжает вниз в ближние ряды и проигрывает их линиям сетки — читается как «под водой». Высотного члена в глубине для этого не нужно, знак и так верный. То же самое в редакторе: `render_core::OverlayRenderer` даёт grid-каналу отдельный пайплайн с LESS_EQUAL + depth write (`WorldRenderer` считает per-corner z по той же конвенции `z_range`, что 3D-пассы), cursor-канал остаётся ALWAYS без записи, спрайты painter-порядком глубину не тестируют.

Хайграунд «висел в воздухе»: земля рисовалась сырой текстурой рядом с освещённым мешем, без единого света, теней и AO. Сейчас оба пасса живут в одной световой модели (`AtlasRenderer` + `SceneStitch.h/.cpp`):

- **Кадр — два этапа.** `AtlasRenderer::prepare(SceneFrame)` (перестройка меш-кэшей, AO-поле, shadow-пасс) вызывается **до** открытия swapchain-пасса, `render(SceneFrame)` — внутри него. Offscreen-пасс внутри swapchain-пасса открыть нельзя, поэтому разделение обязательное.
- **Общий блок юниформ** `SceneStitchParams` (солнце, ортобазис тени, тон, силы AO/тени) идёт в оба FS. Ground-пасс берёт его целиком, cliff-пасс — только «ядро» (`kStitchCoreBytes`, без `ao_rect`): GL-драйвер выкидывает неиспользуемые юниформы, и sokol на каждом старте ругался `GL_UNIFORMBLOCK_NAME_NOT_FOUND_IN_SHADER`. По той же причине у cliff-пасса нет своего `light_dir` — солнце одно на сцену.
- **Земля пишет глубину** (`kGroundDepth`, одна константа за всей сценой) и несёт мировые координаты в `TexVertex` — `worldFromField()` инвертирует `DiamondIsometry::nodeToField`, так что фрагмент земли знает свою клетку и может сэмплить AO-поле и shadow map в кадре меша.
- **Контактное AO** — CPU chamfer distance transform от контура хайграунда (`buildContactAoField`, кэш по `LandBrush::version()`), выгружается в R8; в шейдере расстояние нормировано `kAoMaxDistanceCells`, ширина полосы — `aoRadius` (в клетках), сила — `aoStrength`. Та же сила поднимается по самой стене (`aoWallFade` — высота затухания в единицах меша, едет в cliff-шейдер через `CliffFsParams::params7.w`): если затемнять только землю, камень прямо над ней остаётся светлым и шов, который AO прячет, наоборот подчёркивается. Ключевое: маска берётся **субклеточная**, по тому же правилу частичного заполнения, что рисуют превью-тайлы (`diamondNodeFill` в `LandBrush.h`, общая с `FlatAtlasGenerator`) — клетка это ромб с нодой в каждом углу, и наполовину зажжённая клетка залита клином, а не целиком. С побитовой «клетка занята / не занята» затемнение отступает от диагональной стены на целую клетку и обводит границы клеток, а не сам клиф. Отсюда 8 текселей на клетку (клин у половинной клетки идёт через центр) и дробный посев chamfer'а по линейному пересечению нуля: округление контура до целых текселей даёт лесенку на косых стенах.
- **Shadow map выключен по умолчанию** (`SceneStitchSettings::shadowsEnabled = false`, пасс при этом даже не рендерится): жёсткая солнечная тень поперёк тайлов спорит с освещением, уже запечённым в атласной графике, а стыковку тянет контактное AO. Сама реализация оставлена под галкой — ортопроекция солнца (`buildSunBasis`) в **R32F color attachment** (+ depth attachment для видимости): depth-only пассов и сэмплирования depth-текстур в репо нет вообще. Сэмплер обязан быть `NONFILTERING` / `UNFILTERABLE_FLOAT` (float-таргет не гарантированно фильтруемый), PCF 3×3 руками. Высота меша приводится к клеточным единицам через `isoHeightToWorld(halfW, halfH, heightScale)`, иначе тень не совпадёт по длине с силуэтом.
- **Материалы стыка** (юниформы, без ребилда меша): рефлекс травы снизу и тон неба сверху, затемнение кромки по per-vertex `rim`, у верха плато свои тинт/яркость/тайлинг/поворот UV — он делит `grass.png` с землёй и без этого читается как её продолжение.
- **Два эффекта выключены по умолчанию, но код оставлен:** травяная юбка на подошве стены (`SeamParams::overgrowth = 0`) даёт плоские зелёные кляксы по камню, читающиеся как ошибка текстуры, а кольцо валунов (`ScreeParams::enabled = false`, `appendScreeRing` — дописывает валуны в тот же cliff-поток вершин с `groove = -1` как маркером «палитра стены») рассыпает одинаковую процедурную гальку. И то и другое подножие хочет получить геометрией: отдельной кистью пропов с набором, который подбирает художник под окружение. В шейдере у юбки есть явный гейт `step(1e-4, params4.x)` — без него `step()` против нулевого порога всё равно срабатывает там, где шум ровно ноль.
- **Направление солнца** правит ламбертом обоих пассов и (если тень включить) её длиной: азимут 3π/4 кладёт тень горизонтально по экрану — иначе она прячется за силуэтом меша, который поднят вверх, — а низкая высота даёт ей длину, на которой её видно.
- Проверка: `--smoke` (в т.ч. CPU-проверки AO-поля и ортонормированности базиса), `--shot` теперь портируемый (glReadPixels в TU с `SOKOL_IMPL`; glad подключать нельзя). На Linux скриншоты — под `xvfb-run`. На macOS у Metal `--shot` нечем читать (readback только в GLCORE-ветке), а системный `screencapture` из терминала без Screen Recording-пермишена отдаёт чёрный кадр — для скриншотов standalone-плейграундов на macOS переконфигурировать с GLCORE-бэкендом (у SDFGeneratedLandscape есть opt-in `-DSDFGL_FORCE_GLCORE=ON`, sokol_app на macOS умеет GL); после проверки вернуть Metal-дефолт.

**HiDPI в sokol_app + ImGui (грабли, стоившие «кисть красит не там, где курсор»).** `sapp_width()/sapp_height()` и `ev->mouse_x/y` — **пиксели фреймбуфера**, а ImGui (и, значит, ширина панели) живёт в **логических точках**: `simgui_new_frame()` сам делит размер на `dpi_scale`, а `simgui_handle_event()` — координаты мыши. Стоит вычесть ширину панели (точки) из позиции мыши (пиксели), и на `dpi_scale = 2` курсор уезжает на пол-панели, а viewport, посчитанный как «(пиксели − точки) × dpi», раздувается вдвое. В HighgroundWithEffects вся сцена (камера, мышь, `SceneFrame::viewW/viewH`) теперь в точках — `dpiScale()`/`windowSize()` в `main.cpp`, — а в пиксели переходит ровно одно место, `sg_apply_viewport`, плюс `glReadPixels` на скриншоте. Проверять это под Xvfb можно: `dpi_scale` sokol берёт из `Xft.dpi` в свойстве `RESOURCE_MANAGER` корневого окна, а голый Xvfb **сбрасывается при отключении последнего клиента** и свойство теряет — ставить его и запускать приложение надо с одного живого X-соединения (питоновский `Xlib` + `xtest` для синтетических кликов).
